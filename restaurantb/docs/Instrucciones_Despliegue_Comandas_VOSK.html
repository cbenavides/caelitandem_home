1. Introducción y Requisitos Previos

Esta guía proporciona las instrucciones detalladas para realizar la instalación, generación de certificados SSL y despliegue del stack LAMP Dockerizado (restaurantb) de forma local en LAN para operar de forma 100% offline.

📌 Prerrequisitos de la Máquina Host:
  • Docker Engine y Docker Compose (versión 2.20+ recomendada).
  • Herramienta mkcert instalada localmente (sudo apt install -y mkcert) para automatización SSL.
  • Conectividad a una red LAN Wi-Fi configurada con IP estática en el servidor (ej: 192.168.1.71).

2. Estándar de Activos Estáticos (web-assets)

Para asegurar el correcto funcionamiento sin conexión de la PWA (Progressive Web App) y mantener la simplicidad y portabilidad del código, se establece la siguiente regla arquitectónica:

⚠️ REGLA DE ORO — Rutas Absolutas sin Enlaces Simbólicos:
Todas las llamadas a archivos estáticos (CSS, Javascript, imágenes, modelos) en las vistas PHP deben utilizar la ruta absoluta de la raíz del servidor web (/web-assets/...). No se permite el uso del prefijo /restaurant/web-assets/ ni el uso de enlaces simbólicos (symlinks) en el sistema de archivos del host.

Razón Técnica y Alineación con PWA:

  1. El Service Worker de la PWA (web-assets/pwa/sw.js) realiza la precarga y caché de los recursos utilizando rutas absolutas de dominio (ej: /web-assets/libs/dexie.min.js). Si los scripts de las vistas PHP solicitaran los archivos bajo una ruta distinta como /restaurant/web-assets/..., el navegador fallaría al recuperar el recurso del caché cuando el dispositivo esté completamente offline.
  2. El volumen configurado en el contenedor Apache mapea el directorio del host ../www directamente al DocumentRoot del contenedor (/var/www/html/). De esta manera, el directorio web-assets es accesible de forma nativa e inmediata bajo el subdirectorio raíz /web-assets/ sin requerir enlaces simbólicos.

3. Procedimiento de Despliegue Paso a Paso

Paso 1: Compilación y Lanzamiento de Contenedores

Acceda a la carpeta de configuración y levante los contenedores en segundo plano:

cd /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor
docker compose up -d --build

El flag --build asegura que la imagen personalizada restaurantb_web:latest se actualice con cualquier cambio en el Dockerfile local.

Paso 2: Generación e Inyección del Certificado SSL Local

El uso del micrófono mediante getUserMedia() en navegadores móviles (Chrome Android) requiere obligatoriamente un contexto seguro (HTTPS). Para configurar esto de forma automatizada, ejecute:

./setup-ssl.sh

Este script realiza las siguientes acciones de forma autónoma:

  • Detecta la IP local de la interfaz de red (ej: 192.168.1.71).
  • Invoca a mkcert para generar un certificado SSL de desarrollo local válido para esa IP, localhost y 127.0.0.1.
  • Copia la clave y el certificado generado en el volumen ssl/ montado en Apache.
  • Publica el certificado raíz de la Autoridad Certificadora (ca.crt) en el directorio raíz web accesible por HTTP para que los dispositivos clientes puedan descargarlo.
  • Reinicia el contenedor de Apache de forma silenciosa.

Paso 3: Instalación de la CA Raíz en Dispositivos Cliente

Para que los navegadores móviles confíen en el canal HTTPS de la red local sin alertas ni bloqueos silenciosos del micrófono:

📱 En Dispositivos Móviles (Android):

  1. Conecte el dispositivo Android a la red Wi-Fi local.
  2. Descargue la CA raíz ingresando al navegador en la URL: http://[IP_SERVIDOR]:6001/ca.crt (ej. http://192.168.1.71:6001/ca.crt).
  3. Vaya a Ajustes / Configuración del teléfono.
  4. Navegue a: Seguridad > Cifrado y credenciales > Instalar certificado > Certificado de CA.
  5. Confirme e instale el archivo ca.crt descargado. Reinicie Chrome.

💻 En Computadoras Cliente (Windows):

  1. Descargue la CA desde la PC cliente ingresando a http://[IP_SERVIDOR]:6001/ca.crt.
  2. Abra el archivo, pulse "Instalar certificado...", elija Usuario actual.
  3. Seleccione "Colocar todos los certificados en el siguiente almacén", pulse Examinar... y elija "Entidades de certificación de raíz de confianza". Finalice la instalación y reinicie el navegador.

4. Cheat Sheet de Comandos Útiles

Acción Comando Propósito / Notas
Detener Stack docker compose down Detiene servicios y redes; los datos de la BD persisten en el volumen.
Ver Estado docker compose ps Muestra contenedores activos, puertos expuestos y estado de salud.
Ver Logs docker compose logs -f web Monitoreo de logs del servidor web (Apache/SSL/PHP) en tiempo real.
Acceso a Consola docker compose exec web bash Abre una terminal bash dentro del servidor web para depuración interna.
