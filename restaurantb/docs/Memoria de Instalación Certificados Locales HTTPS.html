📌 1. Resumen de la Implementación

Para cumplir con las políticas de seguridad de los navegadores web modernos (como Google Chrome en Android) que exigen contextos seguros (HTTPS) para el funcionamiento de la API getUserMedia() y el uso del micrófono para comandas por voz offline (VOSK), se ha instalado y configurado mkcert a nivel de usuario en el servidor local. Se generaron certificados locales válidos tanto para la IP local física del host como para las rutas de desarrollo en bucle local.

Hecho Histórico: Se han removido las dependencias del certificado autofirmado genérico (https://localhost:8443) en el volumen local del host de desarrollo, reemplazándolo por una infraestructura SSL local firmada por una Autoridad Certificadora (CA) propia de la red del restaurante.

📜 3. Bitácora de Comandos Ejecutados

3.1. Descarga e Instalación de mkcert

Se descargó el binario compilado de mkcert y se configuró como ejecutable en el servidor:

wget -O /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor/mkcert https://github.com/FiloSottile/mkcert/releases/download/v1.4.4/mkcert-v1.4.4-linux-amd64
chmod +x /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor/mkcert

3.2. Creación de la Autoridad Certificadora (CA)

Se generó la CA local en la carpeta del usuario `carlos`:

/home/carlos/GitHub/caelitandem_home/restaurantb/contenedor/mkcert -install

Este paso generó la clave privada y pública de la CA en /home/carlos/.local/share/mkcert/.

3.3. Corrección de Permisos en la Carpeta SSL

Dado que la carpeta del volumen de host ssl/ fue creada por el servicio Docker como root, se ejecutó un contenedor temporal Alpine para restablecer el propietario a UID/GID 1000 (carlos):

docker run --rm -v /home/carlos/GitHub/caelitandem_home/restaurantb/ssl:/ssl alpine chown -R 1000:1000 /ssl

3.4. Generación de los Certificados Firmados

Se invocó a mkcert para emitir el certificado firmado para la IP física 192.168.1.71 y los alias locales, guardándolo directamente en la carpeta ssl/ de host:

/home/carlos/GitHub/caelitandem_home/restaurantb/contenedor/mkcert -cert-file /home/carlos/GitHub/caelitandem_home/restaurantb/ssl/server.crt -key-file /home/carlos/GitHub/caelitandem_home/restaurantb/ssl/server.key 192.168.1.71 localhost 127.0.0.1

3.5. Exposición Pública de la CA y Reinicio de Nginx

Se copió el archivo de la CA raíz pública como ca.crt al DocumentRoot de la web para su distribución por red local, y se reinició el contenedor Nginx (stack actual — antes era Apache / servicio web):

cp /home/carlos/.local/share/mkcert/rootCA.pem /home/carlos/GitHub/caelitandem_home/restaurantb/www/ca.crt
docker compose -f /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor/docker-compose.yml --project-directory /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor restart nginx

📱 4. Procedimiento de Instalación en Dispositivos Android

Para habilitar el acceso seguro sin advertencias ("candado verde") y asegurar los permisos nativos de grabación de audio en tablets o smartphones Android, siga estos pasos:

Paso 1: Descargar la CA Raíz

Conecte el dispositivo Android a la red Wi-Fi local del restaurante.

Abra el navegador Google Chrome y visite la siguiente dirección IP para descargar el archivo de la CA:

http://192.168.1.71:6001/ca.crt

Confirme la descarga del archivo ca.crt en su dispositivo.

Paso 2: Registrar en el Almacenamiento

Vaya a los Ajustes o Configuración de Android.

  1. Navegue a: Seguridad > Cifrado y credenciales > Instalar certificado.
  2. Seleccione la opción Certificado de CA.
  3. Android mostrará una advertencia de seguridad. Presione Instalar de todas formas.
  4. Busque en su almacenamiento interno y seleccione el archivo ca.crt descargado.
  5. Asigne un nombre descriptivo al certificado (ej: CA Local Restaurant B) y pulse aceptar.
Nota de Compatibilidad: Con este procedimiento, al visitar https://192.168.1.71:8443 desde cualquier dispositivo de la red local, el navegador Chrome mostrará el candado de seguridad cerrado en verde, permitiendo que la PWA registre correctamente el Service Worker y acceda al micrófono.

💻 5. Procedimiento de Instalación en Computadoras y Laptops (Clientes en LAN)

Si deseas acceder al sistema web desde computadoras portátiles o de escritorio en la misma red local del restaurante mediante Chrome u otro navegador, debes instalar la CA raíz en el sistema operativo cliente:

🪟 En Laptops con Windows

  1. Descarga la CA desde la laptop cliente ingresando a:
    http://192.168.1.71:6001/ca.crt.
  2. Haz doble clic sobre el archivo ca.crt descargado y pulsa "Instalar certificado...".
  3. Elige "Usuario actual" y haz clic en Siguiente.
  4. Selecciona la opción "Colocar todos los certificados en el siguiente almacén".
  5. Haz clic en Examinar... y selecciona la carpeta "Entidades de certificación de raíz de confianza". ¡Este paso es indispensable para dar validez de CA!
  6. Haz clic en Aceptar, Siguiente y Finalizar. Confirma la advertencia de seguridad de Windows pulsando "Sí".
  7. Reinicia Google Chrome.

🍎 En Laptops con macOS

  1. Descarga la CA desde la Mac en:
    http://192.168.1.71:6001/ca.crt.
  2. Haz doble clic sobre ca.crt para abrir el gestor de Acceso a Llaveros (Keychain Access).
  3. Arrastra el certificado a la categoría Certificados del llavero Inicio de sesión (login) o Sistema.
  4. Haz doble clic sobre el certificado (ej: mkcert carlos@...), expande la pestaña Confianza (Trust).
  5. En Al usar este certificado selecciona "Confiar siempre" (Always Trust).
  6. Cierra la ventana, ingresa tu contraseña de Mac y reinicia Chrome.

🐧 En Laptops con Linux (Ubuntu/Debian)

  1. Descarga la CA en tu máquina: wget http://192.168.1.71:6001/ca.crt
  2. Copia el certificado al almacén del sistema: sudo cp ca.crt /usr/local/share/ca-certificates/ca.crt
  3. Actualiza los certificados de confianza: sudo update-ca-certificates
  4. Para Chrome/Chromium (que usan su propia base de datos NSS), registra el certificado ejecutando:
    certutil -d sql:$HOME/.pki/nssdb -A -t "CT,C,C" -n "CA Local RestaurantB" -i ca.crt
    (Si no tienes certutil, instálalo con: sudo apt install libnss3-tools).
  5. Reinicia Google Chrome.

🔒 6. Reparación del Controluser de phpMyAdmin (Fix Adicional)

Durante la estabilización, se auditó un fallo recurrente de conexión del usuario de control en phpMyAdmin (mysqli::real_connect(): Access denied for user 'pma'@'172.19.0.2').

Causa Raíz

El script de inicialización de la base de datos bd/init/01_pmadb.sql no se ejecutó debido a la existencia previa de un directorio persistente de base de datos en ../bd/data, ocasionando la inexistencia del usuario de control pma en el motor MariaDB.

Acción Correctiva Ejecutada

Se crearon y asignaron manualmente los privilegios necesarios para el usuario de control ejecutando las siguientes sentencias directamente en el contenedor de base de datos:

docker exec -i restaurantb_db mariadb -u root -pcomite_2026 -e "
  CREATE USER IF NOT EXISTS 'pma'@'%' IDENTIFIED BY 'pma_pass_2026';
  CREATE DATABASE IF NOT EXISTS \`phpmyadmin\` CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  GRANT ALL PRIVILEGES ON \`phpmyadmin\`.* TO 'pma'@'%';
  GRANT SELECT ON \`mysql\`.* TO 'pma'@'%';
  FLUSH PRIVILEGES;
"
docker compose -f /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor/docker-compose.yml --project-directory /home/carlos/GitHub/caelitandem_home/restaurantb/contenedor restart pma

Resultado: Acceso restablecido al 100% y funcionalidades de configuración avanzada de phpMyAdmin totalmente operativas.
