📖 Manual de Operación y Configuración NLP

Guía del Administrador para la gestión del catálogo de voz, sinónimos de cantidad y simulador fonético.

1. Introducción al Sistema de Voz

El sistema de Comandas VOSK utiliza reconocimiento de voz local (offline) ejecutado directamente en los dispositivos de los meseros y cocineros. A diferencia de los motores de voz comerciales que requieren conectividad constante a la nube, este motor descarga e inicializa un modelo acústico liviano en el navegador.

Concepto Clave: Para optimizar la precisión y memoria en entornos ruidosos, el motor de voz restringe su escucha exclusivamente a un conjunto de palabras predefinidas (Gramática). Si un mesero dice palabras ajenas al menú o comandos, el sistema las ignora deliberadamente.

1.1. Estándar de Referencia de Activos Externos (Caché Offline)

Para que la PWA (Progressive Web App) y el Service Worker puedan almacenar en caché local los estilos y scripts del sistema de manera confiable, se sigue la regla de prohibición de bloques embebidos:

  • Toda biblioteca cliente (HTMX, Dexie.js, Chart.js, VOSK libraries) debe residir como archivo externo dentro de www/web-assets/libs/.
  • Todo el código CSS debe enlazarse como archivo externo desde www/web-assets/css/.
  • Todo el código JS debe enlazarse como archivo externo desde www/web-assets/js/.
  • Excepción: Únicamente se permiten scripts de bootstrapping muy breves (menos de 10 líneas) o variables de configuración inicial generadas del lado del servidor inyectadas directamente en el DOM.

2. Gestión de Palabras Clave (Contexto Fonético)

En la pantalla de administración del catálogo (/admin/catalogo), cada producto dispone de un campo editable llamado "Palabras Clave (Dictado VOSK)". Este campo determina cómo buscará e interpretará el motor fonético el dictado del mesero.

2.1. Reglas para Escribir Palabras Clave

  • Escriba las palabras clave separadas por espacios.
  • Use letras minúsculas y evite signos de puntuación.
  • No es necesario colocar acentos, ya que el motor procesa fonemas planos.
  • Incluya el nombre genérico del plato, variaciones locales de taquería y abreviaciones comunes.

2.2. Ejemplos de Configuración en Taquería

Producto Original Palabras Clave Recomendadas ¿Por qué?
Taco al pastor taco pastor tacos pastor pastor trompo carne trompo Permite capturar tanto singular, plural y la jerga de "trompo".
Taco campechano taco campechano tacos campechanos campechano mixto mixtos Soporta "mixto" como sinónimo directo del campechano.
Coca Cola 600ml coca coca cola refresco coca 600 coguita Soporta decir "coca de 600" o "coguita".
Agua de horchata agua horchata agua de horchata orchata Soporta la pronunciación sin la h muda.
Nota Importante: El sistema de coincidencia limpia automáticamente los conectores comunes como de, del, y de la antes de procesar el texto. Así, si la palabra clave es coca 600 y el mesero dice "coca de 600", la coincidencia será del 100%.

3. Configuración de Sinónimos de Cantidad

Los meseros suelen dictar cantidades de forma natural en lugar de números planos. El sistema cuenta con una matriz JSON editable para mapear términos conversacionales a números enteros.

3.1. Formato de Configuración (JSON)

El administrador puede editar esta estructura en la caja de texto correspondiente:

{
  "un": 1,
  "una": 1,
  "uno": 1,
  "el": 1,
  "par": 2,
  "un par": 2,
  "dos": 2,
  "tres": 3,
  "cuatro": 4,
  "cinco": 5,
  "seis": 6,
  "siete": 7,
  "ocho": 8,
  "nueve": 9,
  "diez": 10
}
Flujo de Análisis: Cuando se dicta un segmento (ej. *"un par de gringas"*), el motor busca en el mapa de sinónimos de mayor a menor longitud. Al detectar *"un par"*, le asigna la cantidad 2 y limpia el término para buscar el producto *"gringas"*.

4. Umbrales de Tolerancia Levenshtein

La distancia Levenshtein mide el número de caracteres que se deben cambiar, agregar o quitar para transformar un texto en otro. Esto ayuda a compensar errores menores de transcripción fonética de VOSK.

4.1. Configuración de Parámetros

  • Umbral de Palabras Largas: Determina la tolerancia para términos con más de 5 caracteres.
    Recomendado: 3 (permite errores como "pastro" en vez de "pastor").
  • Umbral de Palabras Cortas: Determina la tolerancia para términos muy pequeños (≤ 5 caracteres).
    Recomendado: 1 o 0 (evita que palabras pequeñas coincidan erróneamente con otros productos).

5. Uso del Simulador y Validador NLP

La consola del **Simulador de Voz** en el panel administrativo es la herramienta principal para validar los cambios antes de publicarlos a producción.

5.1. Instrucciones de Uso

  1. Realice cambios en los campos de "Palabras Clave" o "Sinónimos" en el lado izquierdo.
  2. Escriba una frase completa en el cuadro del simulador (ej. mesa cuatro dos tacos de pastor sin cebolla y un boing mango).
  3. Haga clic en el botón "Probar Procesamiento".
  4. Revise la salida de depuración de la consola.

5.2. Interpretación de Salidas de Consola

La consola desglosa el procesamiento en cuatro fases:

  • Mesa detectada: Identifica el número de mesa tras el comando "mesa [x]".
  • Segmento: Muestra cada una de las partes de la orden detectadas por conectores ("y", "mas", comas).
  • Cantidad e intérprete: Muestra qué sinónimo de número se detectó (ej. "dos" -> 2).
  • Match & Levenshtein: Indica a qué producto de la base de datos se vinculó el segmento y la distancia de caracteres calculada. Si la distancia supera el umbral configurado, la consola marcará Ningún producto coincide.

6. Versionado, Publicación y Delta Hash

El sistema de comandas opera con control de versiones atómico para asegurar la integridad offline de las PWAs.

6.1. Guardar una Versión

Al completar los cambios en las palabras clave y parámetros de tolerancia, asigne una etiqueta de versión (ej. v1.1.0) y escriba una descripción de los cambios. Al hacer clic en "Guardar Nueva Versión", se registrará un snapshot en la base de datos.

6.2. Publicar a Dispositivos

Las versiones guardadas permanecen en estado borrador (Draft). Para distribuirlas a las tabletas/móviles de los meseros, busque la versión en el historial de la derecha y presione el botón "🚀 Publicar".

Automatización: Al publicar, el sistema calcula un delta_hash único del catálogo. Cuando las terminales de los meseros se conectan al servidor LAN, comparan su hash local y actualizan automáticamente el catálogo fonético sin intervención humana.

7. Resolución de Problemas y Diagnóstico

7.1. El simulador arroja "Ningún producto coincide"

Causa: La distancia de edición supera el umbral.
Solución: Verifique que las palabras clave del producto contengan términos parecidos a lo escrito. Si la frase de entrada es muy corta (ej. "coca"), asegúrese de que el umbral de palabras cortas sea al menos 1 o que la palabra clave de "Coca Cola" contenga exactamente "coca".

7.2. Se detectan cantidades erróneas

Causa: Los sinónimos de cantidad se solapan o no están configurados en minúsculas.
Solución: Abra el JSON de sinónimos, valide que la sintaxis sea correcta (todas las claves deben estar en minúsculas y sin acentos) y que los valores sean enteros numéricos válidos.

7.3. Uso de la Bitácora del Sistema Remoto para Diagnóstico

El sistema cuenta con un visor interactivo de bitácora (/restaurant/logs) accesible para el Administrador y el Cajero desde el Módulo de Caja.

  • Monitoreo de Telemetría: Registra eventos en tiempo real enviados por los navegadores móviles de los meseros (como el conteo de chunks de audio procesados, estado de conexión de Vosk y errores en la carga de modelos de voz).
  • Filtros por Dispositivo: Permite filtrar ingresando la dirección IP o el User Agent del dispositivo para aislar el diagnóstico en terminales específicas.
  • Filtros de Nivel y Texto: Facilita la depuración al filtrar logs por nivel de error (ej. SPEECH_ERROR, SPEECH_INFO, JS_RUNTIME_ERROR) o mediante búsquedas de palabras clave (ej. "compile", "IndexedDB").

8. Control de Acceso, Segmentación de Layouts y Roles Operativos (RBAC)

El sistema de Comandas VOSK cuenta con un motor de autenticación seguro (Delight-Auth) integrado con un modelo de Control de Acceso Basado en Roles (RBAC). Para garantizar una experiencia de usuario óptima y segura en cada puesto de trabajo, el sistema divide sus interfaces en dos arquitecturas visuales distintas: PWA Móvil/Hamburguesa (diseño táctil y de manos libres para el personal de piso y cocina) y Webapp Escritorio (diseño denso para administración y control de caja).

8.1. Diferencias Estructurales de Layout (PWA vs. Webapp)

  • PWA Móvil (Menú Hamburguesa - layout-pwa.php): Diseñado para dispositivos táctiles (teléfonos y tablets) y operaciones de manos libres. Integra el Service Worker nativo (soportando precarga offline-first de assets y bases de datos locales en Dexie.js), barra de estado para micrófono VOSK/diadema, y un menú colapsable (sidebar).
  • Webapp Escritorio (Clásico - layout.php): Diseñado para monitores y equipos fijos que requieren consulta densa de datos y captura por teclado/ratón. Posee una cabecera de navegación superior visible permanentemente y no integra scripts de micrófono o diadema, optimizando el rendimiento.

8.3. Comportamiento Inteligente de Rutas y Redirecciones

  • Auto-Redirección Dinámica: Al ingresar a la URL raíz del sistema (/restaurant/), el middleware de Flight PHP intercepta la sesión. Si el usuario está autenticado, recupera su rol y lo redirige automáticamente a su módulo de aterrizaje correspondiente (ej. un mesero es enviado a /restaurant/mesero, un cajero a /restaurant/caja).
  • Autenticación Unificada por NIP: El inicio de sesión se realiza mediante un PIN de 4 dígitos. El backend procesa el NIP, asocia la cuenta de Delight-Auth y utiliza el encabezado HTMX HX-Redirect para realizar la transición visual sin recargar el navegador de forma brusca.
  • Acceso Denegado (403 Forbidden): Si un usuario intenta escribir manualmente en el navegador una ruta para la cual no tiene permisos asignados en el RBAC (ejemplo: un mesero intentando acceder a /restaurant/admin/catalogo), el middleware denegará la petición inmediatamente, mostrando una pantalla de error 403.

8.4. Monitoreo de Desconexiones (Caja)

  • Alerta Roja de Meseros Offline: En la barra superior, el Cajero tiene un ícono de usuarios. Si aparece en rojo numerado, significa que uno o varios meseros perdieron conexión Wi-Fi por más de 45 segundos.
  • Detalle: Al darle clic, se abre una ventana indicando el nombre del mesero y el tiempo que lleva desconectado para tomar acción (ej. pedirle que se acerque al módem).

8.5. Persistencia de Sesión de 28 Días y Uso Multi-Usuario

  • Garantía de Continuidad Offline (Remember Me): La PWA móvil utiliza tokens persistentes de base de datos a través de Delight-Auth para mantener las sesiones abiertas de forma física por un lapso de 28 días. Esto evita que los mecanismos de suspensión de energía o bloqueo de pantalla en iOS y Android expiren la sesión o borren las cookies del navegador.
  • Intercambio Dinámico de Dispositivos (PIN múltiple): Si varios meseros comparten el mismo dispositivo móvil (p. ej., una tableta fija), al digitar un nuevo NIP, el sistema cierra automáticamente la sesión anterior en el servidor y en la cookie local, e inicia de inmediato la sesión del nuevo mesero con sus propios permisos y bitácoras asociadas, sin dejar rastro del token de sesión previo.
  • Cierre de Turno Seguro: El botón "Cerrar Sesión" en el menú hamburguesa destruye físicamente el token persistente de la base de datos (users_remembered) y del navegador, asegurando que ningún tercero acceda al sistema sin ingresar nuevamente su PIN de 4 dígitos.
💡 Nota de Seguridad Operacional: El flujo de Logout explícito es fundamental para la seguridad del negocio. Si un mesero entrega el dispositivo de forma física al terminar su turno o lo deja en el restaurante, hacer Logout garantiza la destrucción de sus credenciales persistentes, requiriendo su NIP en el próximo login. Si únicamente bloquea la pantalla o cierra el navegador, la sesión se mantendrá activa de forma transparente para agilizar el inicio del siguiente turno.

    10. Distribución e Instalación de la Aplicación en Teléfonos y Tablets (Guía para Gerentes y Cajeros)

    Para que los meseros y cocineros puedan usar el sistema de comandas por voz de forma cómoda, la página web debe instalarse en sus celulares o tablets como una PWA (Aplicación Web Progresiva). Al hacerlo, el sistema se comportará como cualquier otra aplicación normal instalada desde la Play Store o App Store: se abrirá a pantalla completa (sin la barra superior de direcciones web del navegador), consumirá menos batería y no se cerrará de forma accidental.

    10.1. Distribución Automática desde el Servidor

    El sistema está diseñado de tal manera que el servidor central del restaurante (la computadora principal de caja) transmite automáticamente la aplicación a cualquier dispositivo móvil que se conecte a la red Wi-Fi del local. No es necesario buscarla en tiendas oficiales. Solo basta con ingresar a la dirección de red del restaurante en el navegador del teléfono para que se inicie la descarga e instalación.

    10.2. Protocolo de Instalación Paso a Paso

    El gerente o cajero debe configurar las tablets y teléfonos del personal siguiendo estos dos sencillos pasos:

    Paso A: Instalar la Licencia de Seguridad (Certificado de Red)

    Debido a que la aplicación necesita utilizar el micrófono del celular para escuchar las comandas, el navegador (Chrome o Safari) exige por seguridad que la conexión sea totalmente privada y confiable. Para lograr esto, debe instalar un archivo de seguridad llamado ca.crt en cada teléfono:

    1. Descargar el archivo: Abra el navegador del celular y escriba la dirección de descarga directa del certificado (ejemplo: https://<IP_SERVIDOR>:8443/ca.crt, sustituyendo <IP_SERVIDOR> por la dirección IP de su servidor en la red local). Acepte la advertencia de seguridad del browser para descargar el archivo.
      Tip: También se puede generar un código QR que apunte a esta dirección para que el personal lo escanee rápidamente.
    2. Instalar en Android:
      • Una vez descargado el archivo, vaya a la Configuración / Ajustes de su teléfono.
      • Busque la sección de Seguridad y Privacidad (o escriba "Certificado" en la lupa de búsqueda).
      • Seleccione Instalar un certificado y luego toque en Certificado de CA (o Certificado de Wi-Fi).
      • Seleccione el archivo ca.crt descargado y confirme la instalación.
    3. Instalar en iOS / iPhone:
      • Al descargar el archivo desde Safari, toque "Permitir" para descargar el perfil de configuración.
      • Vaya a Ajustes y pulse la opción Perfil descargado (aparece arriba). Toque en Instalar.
      • Vaya a Ajustes -> General -> Información -> Ajustes de certificados de confianza. Busque el certificado del restaurante y active el interruptor para darle confianza total.

    Paso B: Añadir la Aplicación a la Pantalla de Inicio

    • En Android (Google Chrome):
      1. Abra Chrome e ingrese a la dirección del sistema (ejemplo: https://<IP_SERVIDOR>:8443/restaurant/login).
      2. Asegúrese de ver el candado gris cerrado al lado de la dirección de internet, lo que confirma que el paso anterior fue exitoso.
      3. Toque el botón de tres puntos verticales (esquina superior derecha).
      4. Seleccione la opción "Instalar aplicación" (o "Añadir a la pantalla de inicio").
      5. Confirme y espere unos segundos. El icono de la aplicación aparecerá en el menú del teléfono listo para usarse.
    • En iOS / iPhone (Safari):
      1. Abra el navegador Safari e ingrese a la dirección del sistema.
      2. Toque el botón de Compartir (el icono de un cuadro con una flecha hacia arriba).
      3. Desplácese hacia abajo y elija "Añadir a la pantalla de inicio".
      4. Asigne el nombre y presione "Añadir".

    10.3. Actualización y Sincronización del Catálogo Offline

    En operación, el flujo correcto es separar la actualización del catálogo operativo de la actualización técnica de la PWA. El Cajero/Gerente puede validar y forzar sincronización desde la App; el Desarrollador es el único rol que modifica el versionado del Service Worker cuando cambia el código fuente.

    1. Abra el menú lateral izquierdo (icono de hamburguesa) en la interfaz del mesero.
    2. Seleccione la opción Diagnóstico PWA.
    3. Revise Versión del catálogo y Delta Hash. Estos valores indican el estado del menú offline y de las palabras clave usadas por VOSK.
    4. Revise Versión PWA / Service Worker. Este valor muestra el cache técnico activo, por ejemplo comandas-v10, y confirma qué paquete de archivos .js, .css y shell PWA está instalado.
    5. Toque Forzar Sincronización. La App limpia el hash local del catálogo, solicita actualización del Service Worker, recarga la pantalla y vuelve a descargar el menú y la gramática de voz.
    6. Si después de recargar la Versión del catálogo o el Delta Hash no cambian, el menú del servidor no cambió o la red no permitió descargar el catálogo actualizado.
    7. Si después de recargar la Versión PWA / Service Worker no cambia, no hay una nueva versión técnica publicada o el navegador aún conserva el Service Worker anterior hasta completar el ciclo de actualización.

    Rol del Desarrollador: cuando se publican cambios en archivos cacheados de la PWA, el desarrollador debe editar CACHE_NAME en www/web-assets/pwa/sw.js y subirlo a un nuevo identificador incremental, por ejemplo de comandas-v10 a comandas-v11. El Cajero/Gerente no edita ese valor; solo usa Diagnóstico PWA y Forzar Sincronización para validar que el dispositivo tomó la versión publicada.

    10.4. Restablecimiento Total de la App (Limpieza de Datos y Caché)

    Si la App instalada se comporta de manera inestable, no inicia o desea simular una "primera carga limpia" (para volver a ver el asistente de permisos de micrófono y almacenamiento), debe vaciar el almacenamiento físico de la App:

    • En Tablets y Celulares Android (App Instalada):
      1. Sal de la aplicación y ve a la pantalla principal del dispositivo.
      2. Abre los Ajustes / Configuración del sistema Android.
      3. Selecciona la opción de Aplicaciones (o Administrar aplicaciones).
      4. Busca y selecciona la App de Comandas VOSK en la lista.
      5. Toca en Almacenamiento (o Memoria).
      6. Presiona el botón Borrar Datos (o Administrar almacenamiento -> Borrar todos los datos) y confirma. Después, presiona Borrar caché.
      7. Al reabrir la App, se ejecutará el onboarding inicial pidiendo confirmación de micrófono y descarga del modelo acústico.
    • En PC / Computadora (PWA en ventana propia):
      1. Haz clic derecho sobre cualquier parte vacía de la ventana de la App y selecciona Inspeccionar (o presiona la tecla F12).
      2. Se abrirán las Herramientas de Desarrollo (DevTools). Selecciona la pestaña Application (Aplicación) en la barra superior.
      3. En el menú izquierdo, haz clic en la sección Storage (Almacenamiento).
      4. En el panel central, presiona el botón Clear site data (Borrar datos del sitio).
      5. Recarga la App presionando las teclas Ctrl + F5 (o Cmd + Shift + R).

    10.5. Cómo desinstalar la aplicación

    Si necesita retirar la aplicación del teléfono de un operador:

    1. Busque el icono de la aplicación en la pantalla del celular.
    2. Manténgalo presionado y toque en Desinstalar o Eliminar.
    3. Para borrar todos los datos guardados de forma manual: Abra Chrome en el celular, vaya a Configuración -> Configuración de sitios -> Datos almacenados, busque la dirección IP del restaurante y toque en Borrar todo.

    10.6. Problemas Frecuentes y Soluciones Rápidas

    ¿Qué problema ocurre? ¿Por qué pasa esto? ¿Cómo lo soluciono rápidamente?
    No aparece la opción "Instalar aplicación", solo dice "Crear acceso directo". El navegador detecta que no se ha instalado la licencia de seguridad (certificado de red) en el teléfono. Vuelva a realizar el Paso A de esta guía. Asegúrese de que el candado de seguridad aparezca cerrado en el navegador antes de intentar instalar.
    La pantalla de diagnóstico muestra alertas en color naranja o rojo. La aplicación se abrió directamente en el navegador de internet en lugar de abrirse desde el icono instalado de la app. Cierre el navegador. Busque el icono oficial de la app en la pantalla de inicio del teléfono y acceda desde ahí.
    El dictado por voz se detiene o la pantalla de la tablet se apaga sola. El teléfono entró en modo de ahorro de energía o se bloqueó la captura automática. Mantenga el cargador conectado en las tablets de cocina o configure el dispositivo para evitar el apagado de pantalla automático desde los ajustes del sistema.
    La aplicación se cierra sola después de varias horas de uso. Fuga de memoria OOM en el motor WASM de VOSK. Ajuste el parámetro MAX_COMMANDS_BEFORE_RESTART a 50 en la pantalla de ⚙️ Configuración Local para obligar a reiniciar el reconocedor de voz antes de saturar la RAM de la tablet.
