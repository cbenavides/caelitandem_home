🌐 2. Corrección y Saneamiento DNS (Hostinger)

Durante la auditoría inicial de los registros DNS en Hostinger para laesh.mx, se detectó la presencia de un registro de dirección duplicado hacia un servidor compartido antiguo (2.57.91.91).

⚠️
Riesgo Resuelto (Round-Robin DNS): Mantener dos registros A provocaba que el 50% de las peticiones cayeran en Hostinger en lugar de la VM OCI, fallando la validación del reto HTTP-01 de Certbot. Se procedió a eliminar la IP 2.57.91.91.

CNAME www laesh.mx 300 s VÁLIDO

⚙️ 3. Permisos de Traversal y Virtual Host Nginx

Para permitir que el proceso de Nginx (www-data) pueda ingresar al directorio personal del usuario ubuntu en la VM OCI, se aplicó traversal seguro:

sudo chmod o+x /home/ubuntu
sudo chmod -R o+rX /home/ubuntu/n8n-php/mvps/whatzmeapi_tests

Configuración aplicada en /etc/nginx/sites-available/laesh.mx:

# ==============================================================================
# Nginx Config — laesh.mx / www.laesh.mx (OCI VM)
# Webroot POC: /home/ubuntu/n8n-php/mvps/whatzmeapi_tests/
# ==============================================================================

server {
    listen 80;
    listen [::]:80;
    server_name laesh.mx www.laesh.mx;

    root /home/ubuntu/n8n-php/mvps/whatzmeapi_tests;
    index index.php index.html index.htm;

    access_log /var/log/nginx/laesh-access.log;
    error_log  /var/log/nginx/laesh-error.log warn;

    location / {
        try_files $uri $uri/ /index.php?$args;
    }

    # Procesamiento PHP-FPM Nativo (socket activo php8.1-fpm.sock)
    location ~ \.php$ {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php8.1-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    }

    location ~ /\.(ht|git|env) { deny all; return 404; }
}

🔄 5. Protocolo Paso a Paso para Deshacer / Revertir la POC

A continuación se detallan las 3 alternativas operativas para remover la prueba del sandbox según el objetivo deseado:

  • Opción A: Desactivar la POC dejando el dominio en mantenimiento / 404 (Deshacer enlace):

    Simplemente remueve el symlink activo de Nginx y recarga el servicio. El certificado SSL continuará guardado de forma segura en Certbot para cuando desees volver a activarlo:

    ssh oci-vm "sudo rm -f /etc/nginx/sites-enabled/laesh.mx && sudo nginx -t && sudo systemctl reload nginx"
  • Opción B: Cambiar el Webroot hacia la WebApp Definitiva LAESH (ej. laesh-swbldi):

    Si deseas que https://laesh.mx/ apunte al sistema final LAESH en lugar del sandbox de pruebas, edita la directiva root en el VHost:

    ssh oci-vm "sudo sed -i 's|/home/ubuntu/n8n-php/mvps/whatzmeapi_tests|/opt/laesh/www/laesh-swbldi/website|g' /etc/nginx/sites-available/laesh.mx && sudo nginx -t && sudo systemctl reload nginx"
  • Opción C: Limpieza Total (Eliminar VHost y Certificados SSL):

    Si deseas borrar por completo la configuración VHost y retirar los certificados emitidos por Certbot:

    ssh oci-vm "sudo rm -f /etc/nginx/sites-enabled/laesh.mx /etc/nginx/sites-available/laesh.mx && sudo certbot delete --cert-name laesh.mx && sudo nginx -t && sudo systemctl reload nginx"
