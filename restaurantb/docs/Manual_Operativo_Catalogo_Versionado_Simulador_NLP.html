1. Introducción al Motor NLP de Voz Local

El sistema de Comandas VOSK utiliza una arquitectura No Embebida y orientada al funcionamiento local (LAN). Para lograr que un mesero pueda dictar una orden de comida sin requerir internet y sin tener que memorizar comandos rígidos o robóticos, el sistema combina un modelo acústico offline (VOSK WASM) con un motor de procesamiento de lenguaje natural (NLP) ligero ejecutado localmente.

SSOT (Single Source of Truth) El catálogo maestro de productos y su configuración de palabras clave fonéticas reside en la base de datos centralizada. Los dispositivos móviles (PWAs) sincronizan este catálogo de forma perezosa mediante la validación de un identificador de cambio único: el Delta Hash.

2. Funcionamiento Interno del Intérprete Fonético

Cuando el operador o mesero dicta una frase, la transcripción cruda se procesa en el cliente o el servidor siguiendo cinco etapas deterministas:

2.1. Normalización de Texto

La frase de entrada se convierte a minúsculas, se eliminan acentos (NFD normalization) y caracteres especiales, y se colapsan espacios en blanco múltiples.

2.2. Extracción del Número de Mesa

Se busca el patrón "mesa [identificador]". El identificador puede ser un dígito directo (ej. "3") o una palabra ("tres"), la cual se mapea mediante el diccionario de sinónimos de cantidad. Una vez extraído, el bloque correspondiente a la mesa se retira de la frase para no interferir en el análisis de productos.

2.3. Segmentación de Ítems

La frase restante se segmenta utilizando conectores gramaticales como "y", "mas" o comas. Por ejemplo:
"dos tacos de pastor con todo y un boing de mango" → ["dos tacos de pastor con todo", "un boing de mango"].

2.4. Extracción de Cantidades y Notas

  • Cantidad: Se busca un número al inicio del segmento (dígito o palabra sinónimo). Si no se detecta ninguno, se asume la cantidad por defecto de 1.
  • Notas Modificadoras: Se detectan cláusulas que inicien con "sin" o "con" al final del segmento (ej. "sin cebolla", "con queso") y se extraen como notas de cocina.

2.5. Coincidencia Fonética (Distancia Levenshtein)

El fragmento limpio del producto se compara contra el catálogo de palabras clave utilizando el algoritmo de Distancia Levenshtein. Para prevenir colisiones y falsos positivos:

Tipo de Palabra Longitud del Input Umbral Máximo Sugerido Ejemplo de Entrada Coincidencia Catálogo
Corta ≤ 5 caracteres 1 error de letra "coca" (Lev. 1) coca (keywords: "coca chesco")
Larga > 5 caracteres 3 errores de letra "pastor" (Lev. 0) tacos al pastor

3. Manual de Uso: Panel de Dataset & Grammar Manager

Ubicado en /restaurant/admin/catalogo, este módulo web permite a los gerentes y administradores controlar el comportamiento semántico del sistema:

+------------------------------------------------------------+ | [Panel Izquierdo: Editor] [Panel Derecho: Simulador] | | * Tabla de Palabras Clave * Caja de Texto de Voz | | * Umbrales Levenshtein * Consola de Coincidencias | | * Sinónimos de Cantidad * Historial de Versiones | +------------------------------------------------------------+

3.1. Edición de Palabras Clave

En la tabla interactiva se listan los productos activos. Para cada producto se puede definir un listado de términos clave separados por espacios.
Tip de Taquería: Agregue modismos locales. Por ejemplo, para el producto "Refresco 600ml", configure las palabras clave: "coca chesco refresco chesco".

3.2. Gestión de Sinónimos de Cantidad

Formateado en JSON, este mapa traduce palabras dictadas a enteros de control: 

{
  "un": 1, "una": 1, "uno": 1,
  "par": 2, "dos": 2, "pareja": 2,
  "tres": 3, "cuatro": 4, "cinco": 5
}

3.3. Creación y Publicación de Versiones

  1. Rellene la Etiqueta de Nueva Versión (ej. v1.2.0) y la Descripción.
  2. Haga clic en Guardar Nueva Versión. El servidor generará un MD5 único (Delta Hash) y creará una instantánea en la tabla versiones_catalogo.
  3. En la lista inferior, haga clic en 🚀 Publicar sobre la versión deseada. Esto la marca como activa para todos los clientes en red.

4. Simulador de Voz y Coincidencia NLP

La sección de validación permite probar de forma interactiva la frase antes de publicarla a los dispositivos móviles.

Propósito del Simulador Permite asegurar que los operadores puedan hablar con soltura natural ("coca de seiscientos", "sin cebolla") sin fallos de coincidencia de distancia de caracteres.

Al pulsar ⚡ Probar Procesamiento, la consola muestra en tiempo real la interpretación: 

// Consola del Intérprete Fonético
Texto recibido: "mesa tres dos tacos de pastor sin cebolla"
Mesa detectada: #3
----------------------------------------
Segmentos y coincidencia de productos:
> Segmento: "dos tacos de pastor sin cebolla"
  - Cantidad interpretada: 2 (sinónimo: "dos")
  - Match: Tacos al Pastor (ID #1)
  - Distancia Levenshtein: 0 contra keywords: "pastor"
  - Notas agregadas: "sin cebolla"

5. Sincronización y Compilación en Caliente (PWA Client)

Para mantener el desempeño óptimo y la resiliencia offline en los dispositivos móviles de los meseros:

  1. El cliente móvil (PWA) verifica periódicamente o al iniciar el archivo /restaurant/api/catalogo/actual.php.
  2. Si el delta_hash devuelto es diferente al guardado en la base de datos local (IndexedDB / Dexie.js), se procede con la descarga perezosa del nuevo catálogo.
  3. Hot-Reloading: Al completarse el guardado, el hilo principal de la PWA envía un mensaje al Web Worker de Voz (vosk-worker.js) para destruir la instancia anterior y re-compilar la Gramática Restringida en segundo plano, sin requerir refrescar la pantalla ni interrumpir la operación del mesero.

6. Guía Práctica para Ejecutar las Pruebas Manuales (UI / VOSK)

Dado que el motor NLP opera primordialmente del lado del cliente y la base de datos puede ser reconstruida, el caché offline del navegador puede desincronizarse. Para realizar pruebas manuales confiables de PWA, siga estos pasos:

6.1. Fase 1: Limpieza Total (Purga de Caché Offline)

  1. Abra Chrome y diríjase al servidor web local (HTTPS en móviles o localhost en PC).
  2. Presione F12 para abrir las DevTools.
  3. Vaya a la pestaña Application (Aplicación).
  4. En el panel izquierdo, haga clic en Storage (Almacenamiento).
  5. Marque todas las casillas (IndexedDB, Service Workers, Local Storage, Caché) y pulse Clear site data.
  6. Recargue la página. Esto forzará la reinstalación del Service Worker, la inicialización de VOSK y la descarga del catálogo fresco.

6.2. Fase 2: Pruebas Funcionales como Mesero (PWA)

  1. Inicie sesión con un rol Mesero.
  2. Presione el micrófono y conceda los permisos.
  3. Protocolo Limpiar/Listo:
    • Dicte: "Mesa uno, dos tacos... ah no, limpiar" → El texto se limpia instantáneamente.
    • Dicte: "Mesa uno, dos tacos al pastor, listo" → Se procesa de inmediato al escuchar "listo", sin esperar silencio (VAD).
  4. Sinónimos, Notas y Tamaños:
    • Dicte: "Mesa cinco, una gringa, dos tripitas y una coca de litro bien fría... listo".
    • Verifique la detección exacta: 1x Gringa, 2x Tripa, 1x Coca-Cola (con extracción del tamaño "de litro" y la nota "bien fría").
  5. Tolerancia Levenshtein Ratio:
    • Dicte: "Mesa dos, un taco de vastor".
    • El sistema aceptará "pastor" si el ratio fonético supera 0.65.

6.3. Fase 3: Pruebas Funcionales como Admin (Panel PHP)

  1. Ingrese como Cajero/Administrador.
  2. Diríjase al panel Catálogo → Simulación de Transcripción.
  3. Escriba las frases anteriores en el cuadro de texto.
  4. Verifique que la descomposición y el cálculo Levenshtein ejecutados en servidor (PHP) tengan paridad del 100% con los resultados de la PWA.

6.4. Validación y Monitoreo local: Diagnóstico PWA

Para asegurar que los meseros en campo cuentan con la última versión del catálogo y validar la integridad de la base de datos local (Dexie.js), se ha integrado un panel de Diagnóstico en tiempo real:

  1. Despliegue el menú de hamburguesa en la esquina superior izquierda de la PWA.
  2. Seleccione la opción 🛠️ Diagnóstico PWA. Se abrirá un modal flotante con los siguientes datos del cliente:
    • Versión de Catálogo: Nombre de la versión activa cargada (ej: v2.0.0).
    • Productos Locales: Número físico de registros almacenados en IndexedDB (debe ser 55 productos para la versión actual).
    • Delta Hash: El identificador único del catálogo para comparar discrepancias con el servidor.
    • Cola Offline (Outbox): Número de comandas capturadas sin conexión que están en espera de ser retransmitidas.
    • Umbrales Levenshtein: Parámetros de tolerancia cargados en caliente desde el admin (corto/largo).
  3. Buscador Offline Integrado: Puede utilizar la caja de texto para filtrar localmente los productos cargados y verificar que sus palabras clave (Keywords) existan físicamente en el dispositivo.
  4. Botón de Sincronización Forzada: En caso de que requiera purgar el catálogo sin abrir la consola de desarrollador del navegador, pulse Forzar Sincronización; esto restablecerá los metadatos y recargará la aplicación en limpio.
