Manual de Mejores Prácticas e Implementación de UX

1. Idempotencia y Prevención de Clics Duplicados en Frontend

Para evitar que un usuario envíe un formulario o pago varias veces haciendo clics rápidos, se delega el control a HTMX. Mediante el atributo hx-disabled-elt, HTMX deshabilita los elementos interactivos seleccionados automáticamente desde el milisegundo en que se inicia la petición AJAX, volviendo a habilitarlos únicamente cuando el servidor retorna la respuesta.

2. Patrón PRG (Post-Redirect-Get) y Tokens de Idempotencia en Backend

Para garantizar que un refresco de pantalla no reenvíe datos críticos a la base de datos:

  • En interacciones HTMX: El controlador de Flight PHP procesa el POST y responde enviando la cabecera especial HX-Redirect en lugar de un redireccionamiento HTTP tradicional.
  • Tokens de un solo uso: Cada formulario incluye un token criptográfico que el backend (apoyado en variables de sesión) invalida tras el primer procesamiento exitoso, rechazando reenvíos.

3. Componente de Espera y Bloqueo de Interfaz (Overlay Spinner)

Se implementa un componente global de bloqueo (un contenedor HTML tipo Overlay con CSS). HTMX gestiona la activación y desactivación de este componente de forma nativa mediante la clase automática .htmx-request vinculada al atributo hx-indicator. Esto congela la pantalla de forma segura durante llamadas lentas de red para evitar clics accidentales.

4. Manejo de Breadcrumbs (Migas de Pan) en Navegación Asíncrona

Debido a que HTMX intercambia fragmentos de HTML dentro de un contenedor principal, los componentes globales (como barras superiores) quedarían obsoletos. Esta arquitectura resuelve esto mediante Intercambios Fuera de Banda (Out of Band Swaps - OOB). Las vistas de Plates incluyen el fragmento actualizado de los breadcrumbs marcado con el atributo hx-swap-oob="true". HTMX extrae ese bloque y actualiza la barra externa automáticamente.
