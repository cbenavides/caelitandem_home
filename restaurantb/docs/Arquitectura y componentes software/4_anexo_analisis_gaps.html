Anexo Técnico: Análisis de Mitigación de Gaps (Brechas)

1. Conflicto de Entornos de Ejecución: Apache/Flight vs. Swoole

El problema: Flight PHP opera bajo el ciclo de vida clásico de Apache (petición entrante, ejecución de scripts de inicio a fin y destrucción de memoria). Swoole, por el contrario, levanta un proceso persistente en memoria por CLI que bloquea y no utiliza las variables superglobales clásicas de PHP como $_SERVER o $_SESSION.

La resolución: Se divide la arquitectura en dos sub-servidores independientes. Apache + Flight PHP retienen el 95% de la aplicación web (lógica de negocio ordinaria, renderizado de formularios con Plates e interacciones CRUD seguras). Swoole se configura en un puerto aislado (ej. :6003) funcionando exclusivamente como un microservicio asincrónico encargado de la pasarela WebSocket de tiempo real y el puente de red directo hacia el contenedor de reconocimiento de voz de Vosk.

2. Desactualización de Delight-PHP/Auth para PHP 8.3

El problema: La librería de Delight-PHP/Auth presenta advertencias de compatibilidad y tipado estricto en las versiones más modernas de PHP 8.3.

La resolución: El sistema no invoca directamente el paquete heredado de manera rígida. Se utiliza el puente nativo de bases de datos extrayendo la conexión PDO limpia desde Medoo ($db->pdo). Adicionalmente, el control fino de la autorización (RBAC) se desacopla de las funciones internas de la librería, creando una tabla relacional independiente en MariaDB 11 que es validada eficientemente mediante métodos mapeados en el ciclo de vida de Flight PHP.
