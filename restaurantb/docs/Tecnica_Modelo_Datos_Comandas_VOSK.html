4. Modelo de Base de Datos (Relacional + Local)

4.1. Módulo de Autenticación y Usuarios (Delight-PHP Auth)

La autenticación se basa nativamente en Delight-Auth. Las cuentas maestras residen en users y se extienden con atributos del restaurante en empleados.

Tabla: users

CREATE TABLE IF NOT EXISTS `users` (
  `id` int(10) unsigned NOT NULL AUTO_INCREMENT,
  `email` varchar(249) COLLATE utf8mb4_unicode_ci NOT NULL,
  `password` varchar(255) CHARACTER SET latin1 COLLATE latin1_general_cs NOT NULL,
  `username` varchar(100) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
  `status` tinyint(3) unsigned NOT NULL DEFAULT '0',
  `verified` tinyint(3) unsigned NOT NULL DEFAULT '0',
  `resettable` tinyint(3) unsigned NOT NULL DEFAULT '1',
  `roles_mask` int(10) unsigned NOT NULL DEFAULT '0',
  `registered` int(10) unsigned NOT NULL,
  `last_login` int(10) unsigned DEFAULT NULL,
  `force_logout` mediumint(7) unsigned NOT NULL DEFAULT '0',
  PRIMARY KEY (`id`),
  UNIQUE KEY `email` (`email`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Tabla: empleados

CREATE TABLE IF NOT EXISTS `empleados` (
    `user_id` int(10) unsigned NOT NULL,
    `nombre_completo` varchar(150) COLLATE utf8mb4_unicode_ci NOT NULL,
    `rol` ENUM('mesero', 'cocinero', 'cajero', 'administrador') NOT NULL DEFAULT 'mesero',
    `diadema_id` varchar(50) COLLATE utf8mb4_unicode_ci,
    `activo` tinyint(1) NOT NULL DEFAULT 1,
    `creado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `actualizado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`user_id`),
    CONSTRAINT `fk_empleado_user` FOREIGN KEY (`user_id`) REFERENCES `users` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

(Las tablas de seguridad `users_remembered`, `users_throttling`, `rbac_permisos`, y `rbac_permisos_usuarios` son provistas por el framework y se detallan en el script DDL 01_auth_schema.sql).

4.2. Módulo de Catálogo Central

Tabla: mesas

CREATE TABLE IF NOT EXISTS `mesas` (
    `id` int(10) unsigned NOT NULL AUTO_INCREMENT,
    `numero` int(10) unsigned NOT NULL,
    `capacidad` int(10) unsigned NOT NULL DEFAULT 4,
    `activa` tinyint(1) NOT NULL DEFAULT 1,

    PRIMARY KEY (`id`),
    UNIQUE KEY `idx_mesa_numero` (`numero`)

Tabla: productos

CREATE TABLE IF NOT EXISTS `productos` (
    `id` int(10) unsigned NOT NULL AUTO_INCREMENT,
    `categoria_id` int(10) unsigned NOT NULL,
    `nombre` varchar(100) COLLATE utf8mb4_unicode_ci NOT NULL,
    `descripcion` text COLLATE utf8mb4_unicode_ci,
    `precio` decimal(10,2) NOT NULL DEFAULT 0.00,
    `codigo` varchar(20) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
    `disponible` tinyint(1) NOT NULL DEFAULT 1,
    `palabras_clave` varchar(255) COLLATE utf8mb4_unicode_ci NOT NULL,
    `creado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `actualizado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    CONSTRAINT `fk_producto_categoria` FOREIGN KEY (`categoria_id`) REFERENCES `categorias` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

4.3. Módulo Transaccional (Comandas y Cierres)

Tabla: comandas

CREATE TABLE IF NOT EXISTS `comandas` (
    `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
    `mesa_id` int(10) unsigned NOT NULL,
    `mesero_id` int(10) unsigned NOT NULL,
    `cocinero_id` int(10) unsigned DEFAULT NULL,
    `texto_transcrito` text COLLATE utf8mb4_unicode_ci,
    `total` decimal(10,2) NOT NULL DEFAULT 0.00,
    `estado` ENUM('pendiente', 'en_preparacion', 'listo', 'entregado', 'cobrado', 'cancelado') COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'pendiente',
    `hora_captura` datetime NOT NULL,
    `creado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `actualizado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    PRIMARY KEY (`id`),
    CONSTRAINT `fk_comanda_mesa` FOREIGN KEY (`mesa_id`) REFERENCES `mesas` (`id`),
    CONSTRAINT `fk_comanda_mesero` FOREIGN KEY (`mesero_id`) REFERENCES `users` (`id`),
    CONSTRAINT `fk_comanda_cocinero` FOREIGN KEY (`cocinero_id`) REFERENCES `users` (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Tabla: detalle_comandas

CREATE TABLE IF NOT EXISTS `detalle_comandas` (
    `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
    `comanda_id` bigint(20) unsigned NOT NULL,
    `producto_id` int(10) unsigned NOT NULL,
    `cantidad` int(10) unsigned NOT NULL DEFAULT 1,
    `precio_unitario` decimal(10,2) NOT NULL,
    `subtotal` decimal(10,2) NOT NULL,
    `estado` ENUM('activo', 'cancelado') COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'activo',
    `cancelado_por_user_id` int(10) unsigned DEFAULT NULL,
    `cancelado_en` timestamp NULL DEFAULT NULL,
    `notas` varchar(255) COLLATE utf8mb4_unicode_ci DEFAULT NULL,
    PRIMARY KEY (`id`),
    CONSTRAINT `fk_detalle_comanda` FOREIGN KEY (`comanda_id`) REFERENCES `comandas` (`id`) ON DELETE CASCADE,
    CONSTRAINT `fk_detalle_producto` FOREIGN KEY (`producto_id`) REFERENCES `productos` (`id`),
    CONSTRAINT `fk_detalle_cancelado_por` FOREIGN KEY (`cancelado_por_user_id`) REFERENCES `users` (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

Tabla: cancelaciones_pendientes

CREATE TABLE IF NOT EXISTS `cancelaciones_pendientes` (
    `id` bigint(20) unsigned NOT NULL AUTO_INCREMENT,
    `detalle_comanda_id` bigint(20) unsigned NOT NULL,
    `mesero_id` int(10) unsigned NOT NULL,
    `cocinero_id` int(10) unsigned DEFAULT NULL,
    `estado` ENUM('pendiente', 'aprobada', 'rechazada', 'expirada') COLLATE utf8mb4_unicode_ci NOT NULL DEFAULT 'pendiente',
    `creado_en` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP,
    `respondido_en` timestamp NULL DEFAULT NULL,
    PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci;

4.4. Procedimientos Almacenados Principales

  • RegistrarComanda(mesa, mesero, transcript, JSON_productos): Genera el registro padre en comandas y múltiples hijos en detalle_comandas usando el JSON extraído del modelo de voz, todo dentro de una transacción segura, calculando montos al vuelo.
  • CerrarCuentaMesa(mesa, mesero): Suma los subtotales de todos los productos en estado "activo" para las comandas válidas, registra en tickets, y marca las comandas como "cobradas".

4.6. Directiva Operativa de Consulta (Indexación y Rendimiento)

  • Rendimiento de Autorización: La clave primaria compuesta en rbac_permisos_usuarios indexa los registros agrupados físicamente por user_id.
  • Motor InnoDB: Se aplican cascadas (ON DELETE CASCADE) a nivel lógico estructural para dependencias directas, pero se mantienen transaccionales lógicos de baja por enum para los productos en la vista para conservar la historia.

4.7. Persistencia Offline en Cliente (Dexie.js / IndexedDB)

Para soportar intermitencias en la red Wi-Fi y asegurar una experiencia fluida "Offline-First", la PWA implementa un esquema local utilizando Dexie.js. La estructura está diseñada para sincronización de fondo (Background Sync).

Esquema Dexie.js (ComandasDB)

import Dexie from 'dexie';

export const db = new Dexie('ComandasDB');

db.version(1).stores({
  // Catálogo en caché (sincronizado al iniciar sesión)
  catalog: 'id, categoria_id, nombre, precio, palabras_clave',
  
  // Cola de salida para comandas no enviadas
  outbox_comandas: 'uuid_local, mesa_id, timestamp, sync_status',
  
  // Buzón de notificaciones (respuestas de cocina, alertas)
  notificaciones: 'id, tipo, leido, timestamp'
});

Gestión de Flujos Locales

  • catalog: Permite a VOSK realizar correcciones difusas (Levenshtein) sin consumir latencia de red.
  • outbox_comandas: Cuando el dictado termina, la orden entra aquí. Si hay red, se despacha y borra. Si no, se retiene y el Service Worker la envía cuando regresa el Wi-Fi.
  • notificaciones: Almacena los últimos 20 mensajes con estado de lectura visual. Previene el efecto de "Voz Fantasma" eliminando mensajes obsoletos (TTL > 5 seg).

5. Registro de Implementación (Sesión Actual)

Durante la presente fase de desarrollo, se lograron los siguientes hitos de integración e infraestructura base:

  • Creación Automatizada de la Base de Datos: Se desarrolló un script orquestador en Bash (setup.sh) que extrae de manera dinámica las credenciales del entorno MCP y aprovisiona la base de datos vcd01 junto con los usuarios transaccionales y datos semilla.
  • Unificación de Autenticación (Delight-Auth): Se crearon y conectaron las tablas maestras de seguridad de Delight-PHP (users, users_remembered, users_throttling) de manera independiente a las tablas operativas (empleados).
  • Procedimientos Almacenados Seguros: Implementación de RegistrarComanda y CerrarCuentaMesa para encapsular la lógica transaccional y el cálculo dinámico de subtotales a nivel de motor de datos.
  • Optimización (Índices SQL): Se incluyó un script dedicado (06_indexes.sql) para la creación de índices BTREE sobre las columnas estado y hora_captura de las comandas, optimizando el renderizado del KDS de cocina y los cierres de mesa.
  • Generación de Activos PWA (Dexie.js): Se estructuró físicamente el almacenamiento local (Offline-First) descargando dexie.min.js para acceso LAN, y desarrollando el módulo db.js (Definición de ComandasDB) y sw.js (Service Worker para interceptar eventos Background Sync). Todo dentro del directorio web-assets/ accesible localmente.
