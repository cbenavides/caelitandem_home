4.3. Procedimientos Almacenados Principales

  • RegistrarComanda(mesa, mesero, transcript, JSON_productos): Genera el registro padre en comandas y múltiples hijos en detalle_comandas usando el JSON extraído del modelo de voz, todo dentro de una transacción segura, calculando montos al vuelo.
  • CerrarCuentaMesa(mesa, mesero): Suma los subtotales de todos los productos en estado "activo" para las comandas válidas, registra en tickets, y marca las comandas como "cobradas".

4.5. Directiva Operativa de Consulta (Indexación y Rendimiento)

  • Rendimiento de Autorización: La clave primaria compuesta en rbac_permisos_usuarios indexa los registros agrupados físicamente por user_id.
  • Motor InnoDB: Se aplican cascadas (ON DELETE CASCADE) a nivel lógico estructural para dependencias directas, pero se mantienen transaccionales lógicos de baja por enum para los productos en la vista para conservar la historia.

4.6. Persistencia Offline en Cliente (Dexie.js / IndexedDB)

Para soportar intermitencias en la red Wi-Fi y asegurar una experiencia fluida "Offline-First", la PWA implementa un esquema local utilizando Dexie.js. La estructura soporta las nuevas adiciones funcionales (áreas, comensales, modificadores y métodos de fallback) mediante sincronización de fondo (Background Sync).

Diagrama Entidad-Relación (Local IndexedDB)

erDiagram CATALOGO { int id PK int categoria_id string nombre float precio } OUTBOX_COMANDAS { string uuid_local PK int area_id int mesa_id int personas string captura } OUTBOX_COMANDAS ||--|{ DETALLE_LOCAL : "1:N contiene (Array JSON)" DETALLE_LOCAL { int producto_id int cantidad string modificadores } ADMIN_OUTBOX { string uuid_local PK string action_type string payload } NOTIFICACIONES { int id PK string tipo boolean leido }

Esquema Dexie.js (ComandasDB)

import Dexie from 'dexie';

export const db = new Dexie('ComandasDB');

// Se incrementa la versión a 2 para soportar la extensión del modelo
db.version(2).stores({
  // Catálogo en caché (sincronizado al iniciar sesión)
  catalog: 'id, categoria_id, nombre, precio, palabras_clave',
  
  // Cola de salida extendida para comandas (soporta comensales y método de captura)
  outbox_comandas: 'uuid_local, area_id, mesa_id, numero_personas, metodo_captura, timestamp, sync_status',
  
  // Buzón de notificaciones (respuestas de cocina, alertas)
  notificaciones: 'id, tipo, leido, timestamp',
  
  // Cola de salida para acciones administrativas UI (Transferencias, Descuentos)
  admin_actions_outbox: 'uuid_local, action_type, payload, timestamp, sync_status'
});

Gestión de Flujos Locales

  • catalog: Permite a VOSK (y al input manual) realizar parseo y correcciones difusas (Levenshtein) de productos y modificadores sin latencia de red.
  • outbox_comandas: Retiene la orden validada (ya sea por voz o teclado fallback) con sus modificadores y comensales. Si hay red, se despacha; si no, el Service Worker la envía al reconectar.
  • admin_actions_outbox: Garantiza que acciones críticas de UI (como transferir mesa o autorizar descuento global con PIN) no se pierdan si la red falla en el instante del envío.
  • notificaciones: Almacena los últimos 20 mensajes. Previene el efecto de "Voz Fantasma" eliminando mensajes obsoletos (TTL > 5 seg).
