Guía Maestra y Especificación Técnica: Reconocimiento de Voz Offline con Vosk

Documento unificado y consolidado que detalla las estrategias comerciales, análisis de viabilidad, especificaciones de hardware, optimizaciones de código local (WebAssembly/IndexedDB), arquitectura de integración frugal e infraestructura de base de datos para el cobro y control de comandas por voz.

🚀 1. Viabilidad de Vosk Browser en Producción

Vosk Browser utiliza WebAssembly (WASM) para ejecutar modelos de reconocimiento de voz directamente en el navegador del cliente de forma 100% local. A continuación, se detalla el análisis de viabilidad para su despliegue comercial:

Ventajas Clave:

  • Privacidad Total: El procesamiento matemático del audio se realiza en el hilo secundario del navegador. El audio capturado nunca viaja a servidores externos, garantizando el cumplimiento de normativas de confidencialidad de datos.
  • Costo Operativo Cero: Al delegar el procesamiento en el dispositivo cliente, el servidor central no sufre sobrecarga por transcripción de audio, eliminando facturaciones recurrentes por consumo de APIs en la nube.
  • Operación sin Internet: Una vez descargado el modelo de lenguaje de forma inicial en el navegador, el sistema funciona de manera autónoma sin requerir una conexión activa a internet.

Limitaciones y Desventajas:

  • Carga de Descarga Inicial: El modelo de lenguaje ligero en español (vosk-model-small-es-0.42) pesa aproximadamente 39 MB en formato comprimido. La primera carga del sistema requiere esta descarga, que puede tardar según la velocidad de la red.
  • Consumo de Memoria RAM: El motor WASM decodificando audio mantiene el modelo directamente en la memoria RAM del navegador. Esto demanda un consumo aproximado de 150 MB a 250 MB de RAM adicionales durante el reconocimiento.
  • Consumo de Batería en Móviles: El cálculo continuo del algoritmo de Viterbi en Kaldi exige un procesamiento matemático intensivo de la CPU, elevando el consumo de batería en teléfonos celulares de gama baja.
💡 Buenas Prácticas de Implementación en Producción:
1. Caché con IndexedDB: Almacena el modelo de lenguaje de Vosk en la base de datos IndexedDB del navegador para evitar descargas en visitas subsecuentes.
2. Web Workers (Hilos Secundarios): Ejecuta el reconocedor dentro de un Web Worker para que la UI no se congele durante la decodificación de audio.
3. Gramática Restringida (Words List): Limita el diccionario a las palabras del catálogo del negocio para elevar la precisión de captura al 99% bajo entornos ruidosos.

🎙️ 3. Las Dos Formas de Implementar Reconocimiento de Voz en Dispositivos

A continuación se detallan los dos caminos de desarrollo técnico para integrar captura de voz en aplicaciones:

Forma 1: Enfoque Nativo Híbrido (Web Speech API)

Utiliza el motor de voz del sistema operativo del dispositivo (Google Voice Services en Android). Es ideal para prototipado rápido pero depende de conexión a internet para transcribir y varía en precisión según el fabricante.

Código de Síntesis de Voz (Text-to-Speech)

const mensaje = new SpeechSynthesisUtterance("¡Hola! ¿En qué puedo ayudarte hoy?");  
mensaje.lang = 'es-MX';  
mensaje.rate = 1.0;  
mensaje.pitch = 1.0;  
window.speechSynthesis.speak(mensaje);

Código de Reconocimiento de Voz (Speech-to-Text)

const SpeechRecognition = window.SpeechRecognition || window.webkitSpeechRecognition;
if (!SpeechRecognition) {
    console.error("Este navegador no soporta la API nativa de voz.");
} else {
    const recognition = new SpeechRecognition();
    recognition.lang = 'es-MX';  
    recognition.continuous = false;  
    recognition.interimResults = false;

    recognition.start();  
    recognition.onresult = (event) => {  
        const textoEscuchado = event.results[0][0].transcript;  
        console.log("Transcripción nativa: " + textoEscuchado);  
    };  
}

Forma 2: Implementación 100% Offline con Vosk-Browser (WASM)

Descarga un modelo comprimido por única vez y ejecuta todo el procesamiento matemático de forma local en el navegador mediante un Web Worker. Garantiza privacidad absoluta de datos, costo cero de procesamiento en servidor y funcionamiento offline.

<script src="web-assets/js/vosk.js"></script>
<script>
let model;  
let recognizer;  

// 1. Descarga e instala el modelo en caché IndexedDB
async function initVosk() {  
    const modelUrl = 'modelos/vosk-model-small-es-0.42.tar.gz';   
    try {  
        model = await Vosk.createModel(modelUrl);  
        console.log("Modelo Vosk cargado exitosamente.");  
    } catch (error) {  
        console.error("Fallo al cargar el modelo:", error);  
    }  
}

// 2. Configura la captura de audio PCM a 16kHz Mono
async function iniciarEscucha() {  
    const sampleRate = 16000;  
    const stream = await navigator.mediaDevices.getUserMedia({  
        audio: { echoCancellation: true, noiseSuppression: true, channelCount: 1, sampleRate }  
    });

    // Gramática restringida para el negocio
    const vocabularioNegocio = ["uno", "dos", "kilo", "tortillas", "cobrar", "pagar"];
    recognizer = new model.KaldiRecognizer(sampleRate, JSON.stringify(vocabularioNegocio));  
      
    const audioContext = new AudioContext({ sampleRate });  
    const source = audioContext.createMediaStreamSource(stream);  

    // Carga del procesador de audio en el hilo de audio dedicado (AudioWorklet)
    await audioContext.audioWorklet.addModule('web-assets/js/pcm-processor.js');
    const workletNode = new AudioWorkletNode(audioContext, 'pcm-processor');

    workletNode.port.onmessage = (e) => {  
        const pcmBuffer = e.data; // Muestras de audio a 16kHz mono
        if (recognizer.acceptWaveform(pcmBuffer)) {  
            const resultado = recognizer.result();  
            if (resultado.text) {  
                console.log("Texto reconocido:", resultado.text);  
            }  
        } else {  
            const parcial = recognizer.partialResult();  
            console.log("Escuchando:", parcial.partial);  
        }  
    };  

    source.connect(workletNode);  
    workletNode.connect(audioContext.destination);  
}
</script>

📱 4. Requerimientos de Hardware, Software y Capacidad (Android)

Para asegurar una decodificación ágil y evitar cierres del navegador, el hardware cliente de los operadores debe cumplir con los siguientes requerimientos:

Requerimientos de Hardware (Android):

  • Memoria RAM (Crítico): Mínimo 3 GB de RAM (Recomendado: 4 GB o superior). El navegador mantiene el modelo decodificado en la RAM.
  • Procesador (CPU): Procesador de 64 bits (Octa-core de gama media actual o equivalente). La decodificación matemática local demanda potencia física de cómputo.
  • Almacenamiento Interno: Al menos 200 MB libres en disco para la caché de datos de Vosk y el crecimiento de la base de datos IndexedDB.

Requerimientos de Software y Navegadores:

  • Sistema Operativo: Android 8.0 (Oreo) o versiones superiores.
  • Navegador Web: Google Chrome versión 90 o superior (Altamente recomendado por su motor V8 optimizado), o Samsung Internet versión 15 o superior.
  • Permisos del Sistema: Obligatorio que el operador autorice el uso del micrófono seleccionando la opción "Mientras la app esté en uso".

Impacto y Capacidad de Almacenamiento:

  • Modelo Vosk: Ocupa ~50 MB en la caché persistente del navegador tras la primera descarga.
  • Cuota Libre en Chrome: Chrome permite usar de forma local hasta un 20% del espacio libre del disco para la webapp (~7.9 GB libres en un dispositivo con 40 GB disponibles).
  • Rendimiento de Datos: Un registro de texto (Nombre + Comanda) pesa aproximadamente 40 Bytes. El espacio disponible en IndexedDB permite guardar millones de transacciones locales.
⚠️ Limitaciones: ¿Cuándo NO usarlo?
  • Dictados largos: Transcribir reuniones, clases completas o podcasts (perderá precisión y puntuación).
  • Audio con mucho ruido de fondo sin diadema adecuada: Si el usuario habla con música alta o motores sin un micrófono direccional, la tasa de error aumenta drásticamente.
  • Vocabulario ultra técnico: No reconocerá términos médicos hiper-específicos, nombres de medicamentos complejos o jerga de programación muy avanzada fuera del diccionario precargado.

🛠️ 5. Optimizaciones de Rendimiento y Memoria (Vosk POC)

Para estabilizar el módulo en terminales de bajo costo, se implementaron las siguientes optimizaciones de ciclo de vida del navegador:

  • Resolución Dinámica de Rutas (Doble Capa): El módulo de voz detecta dinámicamente si se accede desde el directorio raíz o un subdirectorio, recalculando de forma transparente las rutas HTTP de los assets y modelos: 
    // PHP: Carga dinámica del script
<script src="<?php echo file_exists('web-assets/js/vosk.js') ? 'web-assets/js/vosk.js' : '../web-assets/js/vosk.js'; ?>"></script>

// JavaScript: Resolución dinámica del path del modelo
let rootPath = window.location.pathname.substring(0, window.location.pathname.lastIndexOf('/'));
if (rootPath.endsWith('/v-ospv')) {
    rootPath = rootPath.substring(0, rootPath.length - 7);
}
  • Carga Perezosa (Lazy Loading): Para evitar que la página se congele al abrirse, el modelo WASM de ~39MB no se descarga por defecto. La descarga y el Web Worker se inician únicamente cuando el usuario hace clic por primera vez en el botón de captura.
  • Terminación Absoluta del Web Worker: Para recuperar el 100% de la RAM utilizada al finalizar la jornada laboral, el botón de apagado destruye el hilo de procesamiento: 
    voskModel.worker.terminate(); // Destruye el Web Worker
voskModel = null; // Libera el Heap de memoria de JavaScript
    Esto devuelve el consumo de RAM del navegador asociado al modelo a 0 MB.
  • AudioContext como Singleton Global: En lugar de crear múltiples contextos de audio que cuelguen la tarjeta de sonido, se implementó una única instancia global globalAudioCtx inicializada a 16000Hz. Al desactivar el motor, el contexto no se destruye, sino que se suspende vía globalAudioCtx.suspend() y se reactiva vía globalAudioCtx.resume() al encenderlo nuevamente.
  • Procesamiento en Hilo de Audio Dedicado (AudioWorklet): Migración del obsoleto ScriptProcessorNode a AudioWorkletNode para procesar la recolección de muestras PCM a 16kHz en un hilo nativo de baja latencia del sistema operativo. Esto evita micro-congelamientos y jitter causados por la carga de procesamiento del hilo principal de la interfaz web.
  • Prevención de Apagado de Pantalla (Screen Wake Lock): Integración de la API navigator.wakeLock para solicitar un bloqueo de suspensión de pantalla de forma activa mientras el motor de dictado por voz se encuentre grabando, previniendo que el sistema operativo suspenda el procesamiento de WebAssembly.
  • Persistencia en Segundo Plano (Audio Wake Lock): Reproducción de una pista de audio muda en bucle infinito en segundo plano para notificar al kernel del dispositivo (especialmente Android) que la pestaña sigue operando multimedia activa, evitando que el recolector de procesos de background mate el Web Worker de Vosk.

    • Eficiencia: El tendero dicta las órdenes de forma natural mientras empaca la mercancía: "dos kilos de tortillas, un paquete de totopos, diez pesos de masa".
    • Ventaja: Vosk procesa localmente la comanda en milisegundos y calcula el total en pantalla sin necesidad de tocar la interfaz de caja.
    • Gaps Técnicos: El motor de gas, cortadoras y amasadoras generan un ruido constante muy elevado (80-90 dB). Se requieren diademas con micrófonos unidireccionales USB de tipo Call Center para aislar el ruido, además de un backend parser de lenguaje para traducir fracciones (ej. "tres cuartos de kilo") a decimales exactos.
    • Automatización y Reparto por Voz: Los repartidores que conducen motocicletas o camiones dictan sus pedidos pendientes en ruta mientras conducen (ej. "Anota 20 kilos para la tiendita de Doña Mary y 5 para la cocina de San Antonio"), permitiendo la sincronización de inventario sin parar el vehículo ni teclear pantallas.
    • Control de Producción Inteligente: Cámaras IoT procesan la entrada de sacos de harina y maíz para calcular el rendimiento de masa contra merma, alertando si el consumo energético (gas/agua) no cuadra con el arqueo diario.

    • Ventaja: El sistema añade las partidas a la cuenta del cliente instantáneamente y previene la contaminación cruzada en el área de preparación.

🔊 10. Ingeniería de Interacción y Conexión de Hardware

En entornos comerciales locales con altos niveles de ruido (música de bares, cortadoras de carne, motores de llanteras), la captura de audio continua es inviable debido a falsos positivos. Se implementa una arquitectura de interacción híbrida basada en Push-to-Talk (PTT) y Gramática Restringida.

A. Flujo de Interacción por Voz (Voice-Picking sin Pantalla)

El operador interactúa con el sistema utilizando la diadema inteligente sin necesidad de mirar una pantalla:

  1. El mesero o carnicero presiona el botón físico de llamada/micrófono de su diadema Poly.
  2. El sistema emite un BEEP de tono agudo en el auricular indicando que el canal de reconocimiento de voz local se ha abierto.
  3. El operador dicta rápidamente el comando: "Mesa cuatro, dos victorias y un mezcal".
  4. El operador suelta el botón o finaliza el dictado. El sistema emite un BEEP de tono bajo de confirmación de captura.
  5. El Web Worker de Vosk procesa el audio localmente en milisegundos usando una gramática cerrada y le dicta de vuelta al oído mediante síntesis de voz (TTS): "Mesa 4: 2 victorias y 1 mezcal. ¿Confirmar, repetir o corregir?".
  6. El operador responde por voz:
    • "Confirmar" o "Sí": Registra la comanda en la base de datos y emite un doble tono de éxito.
    • "Repetir": Vuelve a reproducir el resumen del pedido auditivo.
    • "Corregir" o "Cancelar": Limpia el buffer temporal para dictar de nuevo.

B. Lógica de Confirmación e Interacción Auditiva (Voice-Picking JS)

Para asegurar un flujo 100% manos libres, el sistema implementa una máquina de estados controlada auditivamente a través de la síntesis de voz nativa (SpeechSynthesis). El operario no requiere desviar la vista del corte o del empaque:

const ESTADOS = { ESCUCHANDO_ORDEN: 'orden', ESPERANDO_CONFIRMACION: 'confirmacion' };
let estadoActual = ESTADOS.ESCUCHANDO_ORDEN;
let pedidoTemporal = null;
let resumenAudioTemporal = "";

// Función para emitir retroalimentación auditiva al operador
function hablarAlOperador(texto) {
    resumenAudioTemporal = texto;
    const mensaje = new SpeechSynthesisUtterance(texto);
    mensaje.lang = 'es-MX';
    mensaje.rate = 1.1; // Velocidad acelerada
    window.speechSynthesis.speak(mensaje);
}

// Procesamiento de los resultados devueltos por Vosk
function onVoskResult(textoDictado) {
    const textoClean = textoDictado.toLowerCase().trim();

    // ESTADO 1: Captura de la comanda inicial
    if (estadoActual === ESTADOS.ESCUCHANDO_ORDEN) {
        pedidoTemporal = interpretarDictado(textoClean);
        const pregunta = `Pedido: ${pedidoTemporal.cantidad} de ${pedidoTemporal.producto}. ¿Confirmar, corregir o repetir?`;
        estadoActual = ESTADOS.ESPERANDO_CONFIRMACION;
        hablarAlOperador(pregunta);
        return;
    }

    // ESTADO 2: Confirmación y mitigación de falsos positivos
    if (estadoActual === ESTADOS.ESPERANDO_CONFIRMACION) {
        if (textoClean.includes("confirmar") || textoClean.includes("si")) {
            hablarAlOperador("Pedido confirmado. Registrando en base de datos.");
            enviarAlServidor(pedidoTemporal);
            reiniciarSistema();
        }
        else if (textoClean.includes("repetir")) {
            hablarAlOperador(resumenAudioTemporal);
        }
        else if (textoClean.includes("corregir") || textoClean.includes("cancelar")) {
            hablarAlOperador("Pedido cancelado. Dicta de nuevo la comanda.");
            reiniciarSistema();
        }
    }
}

function reiniciarSistema() {
    pedidoTemporal = null;
    resumenAudioTemporal = "";
    estadoActual = ESTADOS.ESCUCHANDO_ORDEN;
}

// 1. Inicialización y Gestión de IndexedDB para Pedidos Offline
const DB_NAME = "ComandasOfflineDB";
const STORE_NAME = "cola_pedidos";

function abrirDB() {
    return new Promise((resolve, reject) => {
        const request = indexedDB.open(DB_NAME, 1);
        request.onupgradeneeded = (e) => {
            const db = e.target.result;
            db.createObjectStore(STORE_NAME, { keyPath: "id", autoIncrement: true });
        };
        request.onsuccess = (e) => resolve(e.target.result);
        request.onerror = (e) => reject(e.target.error);
    });
}

// Sincronización automática periódica (FIFO)
async function procesarColaSincronizacion() {
    if (!navigator.onLine) return;
    const db = await abrirDB();
    const tx = db.transaction(STORE_NAME, "readwrite");
    const store = tx.objectStore(STORE_NAME);
    const request = store.getAll();

    request.onsuccess = async (e) => {
        const pedidos = e.target.result;
        for (const ped of pedidos) {
            if (ped.estado_sync === "pendiente") {
                try {
                    const response = await fetch("api/comanda.php", {
                        method: "POST",
                        headers: { "Content-Type": "application/json" },
                        body: JSON.stringify(ped)
                    });
                    const res = await response.json();
                    if (res.status === "success") {
                        store.delete(ped.id); // Borrado FIFO al confirmar envío
                    }
                } catch (err) {
                    console.error("Fallo al sincronizar pedido: ", err);
                }
            }
        }
    };
}

// 2. Algoritmo Fuzzy Matching Levenshtein para Corrección Fonética
function obtenerDistanciaLevenshtein(str1, str2) {
    const track = Array(str2.length + 1).fill(null).map(() => Array(str1.length + 1).fill(null));
    for (let i = 0; i <= str1.length; i += 1) track[0][i] = i;
    for (let j = 0; j <= str2.length; j += 1) track[j][0] = j;
    for (let j = 1; j <= str2.length; j += 1) {
        for (let i = 1; i <= str1.length; i += 1) {
            const indicator = str1[i - 1] === str2[j - 1] ? 0 : 1;
            track[j][i] = Math.min(
                track[j][i - 1] + 1, // Inserción
                track[j - 1][i] + 1, // Eliminación
                track[j - 1][i - 1] + indicator // Sustitución
            );
        }
    }
    return track[str2.length][str1.length];
}

// Asignar el artículo del catálogo más similar al dictado
function corregirFuzzyArticulo(palabraDictada, catalogo) {
    let mejorCoincidencia = palabraDictada;
    let distanciaMinima = 3; // Umbral de tolerancia de caracteres incorrectos

    for (const item of catalogo) {
        const dist = obtenerDistanciaLevenshtein(palabraDictada, item);
        if (dist < distanciaMinima) {
            distanciaMinima = dist;
            mejorCoincidencia = item;
        }
    }
    return mejorCoincidencia;
}

DELIMITER //
CREATE PROCEDURE RegistrarPedidoVoz(
    IN p_telefono VARCHAR(20),
    IN p_articulo_nombre VARCHAR(100),
    IN p_cantidad DECIMAL(10, 3)
)
BEGIN
    DECLARE v_articulo_id INT;
    DECLARE v_precio DECIMAL(10, 2);
    DECLARE v_stock_actual DECIMAL(10, 3);
    DECLARE v_pedido_id INT;
    DECLARE v_subtotal DECIMAL(10, 2);

    START TRANSACTION;

    -- Bloqueo pesimista para lectura segura de stock
    SELECT id, precio, stock INTO v_articulo_id, v_precio, v_stock_actual 
    FROM articulos 
    WHERE nombre = p_articulo_nombre FOR UPDATE;

    IF v_stock_actual >= p_cantidad THEN
        -- Crea cabecera
        INSERT INTO pedidos (cliente_telefono, total) VALUES (p_telefono, 0.00);
        SET v_pedido_id = LAST_INSERT_ID();

        -- Calcula subtotal
        SET v_subtotal = v_precio * p_cantidad;

        -- Inserta detalle
        INSERT INTO detalle_pedidos (pedido_id, articulo_id, cantidad, subtotal) 
        VALUES (v_pedido_id, v_articulo_id, p_cantidad, v_subtotal);

        -- Actualiza cabecera
        UPDATE pedidos SET total = v_subtotal WHERE id = v_pedido_id;

        -- Descuenta inventario
        UPDATE articulos SET stock = stock - p_cantidad WHERE id = v_articulo_id;

        COMMIT;
        SELECT v_pedido_id AS pedido_id, 'success' AS status, v_subtotal AS total_comanda;
    ELSE
        ROLLBACK;
        SELECT 0 AS pedido_id, 'insufficient_stock' AS status, 0.00 AS total_comanda;
    END IF;
END //
DELIMITER ;
