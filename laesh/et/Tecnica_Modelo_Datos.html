4. Modelo de Base de Datos (Relacional)

4.1. Diagrama Entidad-Relación (Backend MariaDB)

Diagrama estructural en notación Crow's Foot que representa las entidades del Bloc Digital y el Sitio Web.

erDiagram USERS { int id PK string email string password string username int roles_mask } EMPLEADOS { int user_id PK "FK a users" string nombre_completo string rol "ENUM: MEDICO, RECEPCION, ADMIN" boolean activo } RBAC_PERMISOS { int id PK string nombre string descripcion } RBAC_PERMISOS_USUARIOS { int user_id PK "FK a users" int permiso_id PK "FK a rbac_permisos" timestamp asignado_el } ESTUDIOS { int id PK string codigo string nombre string categoria string tiempo_procesamiento string muestra_requerida string indicaciones_preparacion boolean activo } ORDENES { bigint id PK int medico_id FK int recepcion_id FK string paciente_nombre string folio_unico string estado "REMITIDO, ATENCION, RESULTADOS, CERRADA" datetime hora_captura } DETALLE_ORDENES { bigint id PK bigint orden_id FK int estudio_id FK string notas } RESULTADOS_PDF { bigint id PK bigint orden_id FK string file_path timestamp fecha_subida } WEB_CONTENIDOS { int id PK string seccion "CMS: Banner, Promocion, Paquete" string titulo string descripcion string imagen_path boolean activo } CONFIGURACIONES { int id PK string clave string valor string descripcion } USERS ||--o| EMPLEADOS : "1:1 tiene" USERS ||--o{ RBAC_PERMISOS_USUARIOS : "1:N tiene" RBAC_PERMISOS ||--o{ RBAC_PERMISOS_USUARIOS : "1:N asignado_a" USERS ||--o{ ORDENES : "1:N emite (médico)" USERS ||--o{ ORDENES : "1:N atiende (recepción)" ESTUDIOS ||--o{ DETALLE_ORDENES : "1:N incluye" ORDENES ||--|{ DETALLE_ORDENES : "1:N contiene" ORDENES ||--o| RESULTADOS_PDF : "1:1 adjunta"

4.2. Diccionario de Datos (Backend MariaDB)

Diccionario de Datos: Autenticación y Usuarios
TablaDescripciónCampos PrincipalesPK / Relaciones (FK)
users Cuentas de autenticación (Delight-Auth) email, password, username, roles_mask, status PK: id
users_* (auxiliares) Tablas nativas auxiliares de Delight-Auth para control de accesos y seguridad users_remembered (sesiones activas), users_throttling (tasa de peticiones), users_audit_log (auditoría de eventos) Relaciones FK a users(id)
empleados Atributos operativos del personal de la clínica nombre_completo, rol (ENUM), activo PK: user_id | FK: user_id -> users(id)
rbac_permisos Catálogo central de permisos del sistema nombre, descripcion PK: id
rbac_permisos_usuarios Asignación Many-to-Many de privilegios (RBAC) asignado_el PK: user_id, permiso_id | FK: user_id -> users(id), FK: permiso_id -> rbac_permisos(id)
Diccionario de Datos: Catálogo Base
TablaDescripciónCampos PrincipalesPK / Relaciones (FK)
estudios Catálogo base detallado, alimentado vía archivo Excel codigo, nombre, categoria, tiempo_procesamiento, muestra_requerida, indicaciones_preparacion, activo PK: id
web_contenidos Motor CMS Frugal para la web pública corporativa seccion (ENUM), titulo, descripcion, imagen_path, activo PK: id
configuraciones Parámetros globales paramétricos del administrador clave, valor, descripcion PK: id
Diccionario de Datos: Transaccional (Bloc Digital)
TablaDescripciónCampos PrincipalesPK / Relaciones (FK)
ordenes Cabecera de la solicitud clínica y su ciclo de vida paciente_nombre, folio_unico, estado, hora_captura PK: id | FK: medico_id -> users(id)
FK: recepcion_id -> users(id)
detalle_ordenes Estudios individuales solicitados por cada orden notas PK: id | FK: orden_id -> ordenes(id)
FK: estudio_id -> estudios(id)
resultados_pdf Almacenamiento y metadatos de los resultados adjuntos file_path, fecha_subida PK: id | FK: orden_id -> ordenes(id)
