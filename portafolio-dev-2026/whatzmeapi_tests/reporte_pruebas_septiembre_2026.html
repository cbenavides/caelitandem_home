5. Bugs Técnicos Identificados y Correcciones Aplicadas

🐛 Bug #1: Rechazo en Edición de Mensaje (Propiedad mensaje vs texto)

Síntoma: Al presionar "Editar Mensaje", la API respondía pero el texto en WhatsApp no se modificaba.

Causa Raíz: El payload utilizaba la propiedad "mensaje". La especificación oficial de Postman exige estrictamente la llave "texto" en PUT /editar-mensaje.

Fix Aplicado: Se corrigió pipeline_mensajeria.php reemplazando el mapa a ['texto' => $mensajeEditado].

🐛 Bug #2: Omisión de Pie de Foto en Imágenes (Propiedad caption vs textoimagen)

Síntoma: La imagen se enviaba al teléfono pero llegaba sin la leyenda o pie de foto.

Causa Raíz: El script enviaba 'caption' => $caption. La API requiere 'textoimagen' => $caption y 'nombrearchivo' => $filename.

Fix Aplicado: Se actualizó test_archivos_masivos.php alineando los parámetros a la especificación nativa.

🐛 Bug #3: Restricción de Frecuencia HTTP 429 Too Many Requests

Síntoma: Al presionar botones de envío consecutivamente rápidos aparecía el mensaje 429 Too Many Requests.

Causa Raíz: La cuenta DEMO opera bajo la política Free Trial (máximo 1 mensaje por minuto / 60s delay).

Solución Operativa: Se estableció la regla de pausa de 60 segundos entre envíos para evitar la saturación del rate limit.

8. Análisis de Viabilidad, Casos de Uso y Plan de Setup: WhatzMeApi + Chatwoot en OCI VM

A solicitud del requerimiento técnico, se realizó la investigación, análisis de factibilidad y diseño de arquitectura para integrar la instancia activa de WhatzMeApi con la plataforma de atención multiagente Chatwoot sobre la infraestructura existente en Oracle Cloud Infrastructure (OCI VM).

🟢 Dictamen de Viabilidad Técnica: 100% VIABLE Y FACTIBLE.
Aunque Chatwoot no posee un conector nativo nombrado "WhatzMeApi" en su menú principal (debido a que solo ofrece accesos directos para la API oficial de Meta y Twilio), Chatwoot incluye el canal agnóstico API Inbox (Canal API). Este mecanismo permite conectar cualquier proveedor de WhatsApp mediante un Middleware Puente. Dado que el motor de automatización n8n ya se encuentra instalado y activo en el puerto 5678 de la VM OCI, el flujo bi-direccional entre WhatzMeApi y Chatwoot se resuelve de forma nativa sin necesidad de desarrollar código adicional.

8.1 Casos de Uso Principales (WhatzMeApi + Chatwoot)

Caso de Uso Descripción Operativa Beneficio Técnico / Comercial
1. Bandeja Multi-Agente Omnicanal para WhatsApp QR Permite a múltiples operadores/agentes atender simultáneamente la misma línea telefónica vinculada en WhatzMeApi, asignando chats, transfiriendo conversaciones y agregando notas privadas. Elimina la limitante de un solo operador en el teléfono físico o WhatsApp Web, centralizando la atención con perfiles y roles.
2. Automatización e Integración con n8n El motor n8n (ya corriendo en la VM) actúa como puente, enrutando mensajes entrantes, capturando leads automáticamente y conectando con CRMs o bases de datos de negocio. Cero desarrollo de microservicios desde cero. Todo el enrutamiento se gestiona con nodos visuales HTTP en n8n.
3. Campañas Masivas con Atención Humana Se envían campañas masivas desde WhatzMeApi Sandbox (POST /enviar-mensaje-muchos-contactos) y las respuestas entrantes de los clientes caen directo a las bandejas de Chatwoot. Combina la potencia de disparo masivo de WhatzMeApi con el seguimiento uno a uno de Chatwoot.
4. Historial Centralizado y Gestión de Adjuntos Chatwoot almacena el historial de chat, audios, imágenes (JPG/PNG) y documentos (PDF/Word) en su base de datos PostgreSQL. Resguardo seguro de evidencias de chat sin saturar el almacenamiento del dispositivo móvil.

  • Compatibilidad con Sandbox: Cero interferencia. WhatzMeApi Sandbox continúa operando sobre PHP-FPM/Nginx bajo /mvps/whatzmeapi_tests/.

8.4 Hoja de Ruta y Plan de Setup (Up & Running en OCI VM)

Etapas de Despliegue Técnico (Setup Plan):
  1. Fase A — Directorio y Docker Compose: Crear /home/ubuntu/chatwoot/ y configurar docker-compose.yml aislando Rails, Sidekiq, postgres:15-alpine y redis:7-alpine.
  2. Fase B — Migración e Inicialización de DB: Ejecutar docker compose run --rm rails bundle exec rails db:chatwoot_prepare para estructurar las tablas iniciales de la aplicación.
  3. Fase C — VHost Nginx y Certificado SSL: Crear la configuración virtual host en Nginx para chatwoot.caelitandem.lat redirigiendo peticiones al puerto interno 3000 y habilitando WebSockets (/cable).
  4. Fase D — Alta de API Inbox en Chatwoot: Crear la bandeja de entrada tipo API Channel en el panel admin de Chatwoot y copiar el inbox_identifier y el API Token.
  5. Fase E — Activación de Flujos Bi-Direccionales en n8n:
    • Flujo 1 (Entrante):** Webhook Trigger (recibe mensaje_recibido de WhatzMeApi) ➔ Nodo Chatwoot (crea o busca contacto por teléfono 521953... y publica mensaje).
    • Flujo 2 (Saliente):** Webhook Trigger (recibe message_created de Chatwoot) ➔ Nodo HTTP Request (ejecuta POST /enviar-mensaje o /enviar-archivo en WhatzMeApi).
