🚀 Novedad: Interfaz Web Integrada y Refactorización RESTful

Acceso a la WebApp: Ya puedes realizar todas las pruebas de forma interactiva desde https://caelitandem.lat/mvps/whatzmeapi_tests/

Consola de Depuración Avanzada: La terminal inferior de la WebApp ha sido mejorada con Syntax Highlighting (resaltado de sintaxis). Ahora las respuestas crudas de la API (JSONs) se renderizan automáticamente con códigos de color para llaves, strings y números, lo que facilita enormemente la lectura de LIDs, IDs de mensajes o URLs multimedia.

Actualización Arquitectónica: La refactorización abarcó la limpieza completa de los métodos HTTP para alinearlos a los estándares RESTful de la API oficial. Ahora utilizamos métodos PUT y DELETE para las modificaciones de mensajes y configuraciones de grupos, pasando los identificadores por la URL en lugar de saturar el Body JSON. También revertimos el envío de multimedia hacia /enviar-archivo para máxima compatibilidad con WhatzMeApi Basic.

Para ejecutar las pruebas desde la WebApp interactiva, solo necesitas seguir 3 pasos:

1. Obtener tu Token Real

Ingresa al dashboard de WhatzMeApi y obtén el token de acceso de tu instancia. Lo necesitarás para ingresarlo directamente en la interfaz web de pruebas.

2. Disponer de Números de Destino Reales

Ten a la mano los números a los cuales se enviarán los mensajes de prueba (deben incluir el código de país sin el símbolo +, ej. 521XXXXXXXXXX para México).

3. Vincular el Dispositivo (WhatsApp)

Asegúrate de haber vinculado tu número de emisor escaneando el código QR en el dashboard oficial de WhatzMeApi. Sin una sesión activa en la instancia, las peticiones fallarán.

Arquitectura de los Scripts: Unitarios vs. Pipelines

El dashboard interactúa con el backend de WhatzMeApi mediante dos tipos de scripts PHP, diseñados para probar diferentes niveles de complejidad:

1. Módulo Unitario (Sesión)

Prueba los endpoints base de forma aislada. Solo requiere el Token.

  • test_sesion.php: Valida el estado de la conexión, obtiene la suscripción, información del usuario, valida si un número de WhatsApp existe, y genera el código QR si la cuenta está desconectada. No guarda estado en memoria.

2. Controladores Interactivos (Flujos Paso a Paso)

A diferencia de una ejecución secuencial robótica, estos scripts han sido refactorizados como controladores atómicos. A través de la WebApp, tú decides el ritmo: presionas un botón, esperas el tiempo que desees, y procedes al siguiente paso.

Magia en Frontend: El Javascript de la página captura automáticamente los identificadores (ej. idMensaje o jidGrupo) del primer paso y los almacena en memoria para usarlos silenciosamente en los siguientes pasos (como editar o eliminar).

  • Gestión de Contactos (test_contactos.php):
    Flujo Interactivo: Puedes obtener la agenda completa (GET /contactos) ➔ Obtener Info y Foto de un número específico ➔ Realizar el ciclo de mapeo inverso de LID a Número ➔ Crear y Guardar nuevos contactos en tu libreta telefónica (PUT /contacto).
  • Archivos y Multimedia (test_archivos_masivos.php):
    Flujo Interactivo: Sube una imagen o audio (OGG) al servidor (OCI VM) y envíalo hacia WhatzMeApi ➔ El frontend guarda en memoria el ID del multimedia ➔ Utiliza el botón de Eliminar Multimedia (DELETE) para borrar el archivo del teléfono destino y permitir un reemplazo limpio.
  • Mensajería (pipeline_mensajeria.php):
    Flujo Interactivo: Calienta el Número (simula "escribiendo...") y Envía el Mensaje Original ➔ Captura el ID del Mensaje ➔ Edita el texto del mensaje enviado (PUT) ➔ Elimina el Mensaje para todos (DELETE).
  • Grupos (pipeline_grupos.php):
    Flujo Interactivo: Crea un Nuevo Grupo (POST) y extrae su ID ➔ Configura permisos a "Solo Admins" (PUT) ➔ Promueve un Participante a Administrador (PUT) ➔ Genera el Link de Invitación.

Alcance de las Pruebas (Gaps Intencionales)

Para mantener la herramienta ligera y enfocada en los flujos principales (Happy Paths), se omitieron intencionalmente algunos endpoints secundarios presentes en la documentación oficial de WhatzMeApi:

  • Desconexión (cerrar-sesion): Omitido para evitar que el probador desconecte su dispositivo por accidente y tenga que volver a escanear el QR.
  • Formatos Niche: No se implementaron los envíos de Encuestas, Ubicaciones o Stickers; ya que los flujos de texto y archivos (imágenes/audio) demuestran de sobra la capacidad de carga del canal.
  • Comandos Secundarios de Grupos: El pipeline demuestra la creación y promoción de roles. Se omitieron llamadas menos críticas como salir-del-grupo, obtener-metadata o la aceptación manual de links de invitación.
  • Campañas Masivas: Los envíos por lotes a múltiples contactos están excluidos de esta herramienta para prevenir bloqueos prematuros (anti-spam) durante las pruebas de desarrollo.
