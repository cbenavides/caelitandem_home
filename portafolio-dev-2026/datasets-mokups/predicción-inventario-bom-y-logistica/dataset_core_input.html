📊 Resumen Ejecutivo del Dataset
Fuentes, estructura y uso por caso de uso

Este documento consolida las fuentes de datos publicas y estructuras recomendadas para alimentar los tres casos de uso de logistica, inventario y BOM predictivo. Se basa en datasets benchmark del sector retail/FMCG, competencias de Kaggle, y literatura academica de optimizacion de inventarios, rutas de vehiculos y analisis de canasta de mercado.

📦 Caso #1 — Inventario Predictivo

Caso #1

Requiere series de tiempo de ventas por tienda/SKU, enriquecidas con calendario, clima y promociones.

  • Walmart Store Sales (Kaggle): 45 tiendas, ventas semanales, features macroeconomicas
  • Rossmann Store Sales (Kaggle): 1,115 tiendas, ventas diarias, promociones, competencia
  • Favorita Grocery (Kaggle): 54 tiendas ecuatorianas, ~125M registros, eventos externos
  • M5 Forecasting (Kaggle): 3,049 productos × 10 tiendas, jerarquia completa

🚛 Caso #2 — Logistica Predictiva

Caso #2

Requiere datos geoespaciales de depositos y tiendas, matrices de distancia/tiempo, y demandas por punto.

  • Solomon Benchmark VRPTW: 56 instancias, 100 clientes, estandar academico
  • Gehring & Homberger VRPTW: 200–1,000 clientes, pruebas a escala real
  • TSPLIB: 198 instancias, 14–85,900 nodos, coordenadas reales
  • Eco-VRP Extended Solomon: Metricas ambientales, emisiones CO2

📦 Caso #3 — BOM Predictivo

Caso #3

Requiere datos de transacciones detalladas (ticket-level), catalogo de SKUs con costos, y historico de promociones/paquetes.

  • Instacart Market Basket Analysis (Kaggle): 3M+ ordenes, 50K+ productos, secuencia de compra. Ideal para analisis de canasta y prediccion de proximo producto.
  • UCI Online Retail (UK): 541K transacciones, 4K+ productos, datos de canasta real con devoluciones.
  • Dunnhumby — The Complete Journey: 2,500 hogares, 250K+ transacciones, promociones, lealtad. Ideal para segmentacion y personalizacion de paquetes.
🔗 Fuentes de Datos Publicas y Benchmarks
Datasets descargables para entrenamiento y validacion

🏪 Walmart Recruiting — Store Sales Forecasting

Kaggle · 2014 · 45 tiendas · ~3 años de datos · Autoridad: Alta

Datos historicos de ventas semanales por departamento para 45 tiendas Walmart. Incluye features de temperatura, precio de combustible, CPI, desempleo, y 5 variables de markdown promocional anonimizadas. Ideal para entrenar modelos de forecasting con variables macroeconomicas.

URL: https://www.kaggle.com/c/walmart-recruiting-store-sales-forecasting/data

Uso: Caso #1 · Entrenamiento de modelo base de forecasting, feature engineering de variables externas.

🏪 Rossmann Store Sales

Kaggle · 2015 · 1,115 tiendas · ~2.5 años · Autoridad: Alta

Ventas diarias de 1,115 farmacias Rossmann en Alemania. Incluye indicadores de promocion (Promo, Promo2), dias festivos, distancia a competencia, fecha de apertura de competencia. Dataset clasico para forecasting retail con promociones.

URL: https://www.kaggle.com/c/rossmann-store-sales/data

Uso: Caso #1 · Entrenamiento con datos diarios, manejo de promociones y competencia.

🏪 Corporacion Favorita Grocery Sales Forecasting

Kaggle · 2018 · 54 tiendas · ~4.5 años · Autoridad: Alta

Ventas diarias de supermercados ecuatorianos. Granularidad por familia de productos (no por SKU individual). Incluye dias festivos locales, terremotos (evento externo inesperado), promociones, y datos de transactions. Dataset masivo (~125M registros).

URL: https://www.kaggle.com/c/favorita-grocery-sales-forecasting/data

Uso: Caso #1 · Manejo de eventos externos (terremotos), escalabilidad a gran volumen.

🏪 M5 Forecasting — Accuracy

Kaggle · 2020 · 3,049 productos × 10 tiendas · 1,941 dias · Autoridad: Alta

Ventas diarias unitarias por producto-tienda de Walmart US. Jerarquia completa: item → department → category → state. Incluye precios de venta y calendario de eventos. Competencia de forecasting jerarquico de alta complejidad.

URL: https://www.kaggle.com/c/m5-forecasting-accuracy/data

Uso: Caso #1 · Forecasting jerarquico, reconciliacion top-down/bottom-up, manejo de precios.

🛒 Instacart Market Basket Analysis

Kaggle · 2017 · 3M+ ordenes · 50K+ productos · Autoridad: Alta

Datos de compras de supermercado online (Instacart). Incluye: ordenes, productos, pasillos, departamentos, secuencia de productos en el carrito, y reordenamiento. Ideal para market basket analysis, prediccion de proximo producto, y analisis de secuencia de compra.

URL: https://www.kaggle.com/c/instacart-market-basket-analysis/data

Uso: Caso #3 · Market basket analysis, deteccion de asociaciones, generacion de candidatos de paquetes.

🛒 UCI Online Retail (UK)

UCI Machine Learning Repository · 2015 · 541K transacciones · 4K+ productos · Autoridad: Media-Alta

Datos transaccionales de una tienda online del Reino Unido (2010–2011). Incluye: InvoiceNo, StockCode, Description, Quantity, InvoiceDate, UnitPrice, CustomerID, Country. Contiene devoluciones (cantidades negativas). Ideal para analisis de canasta de mercado y segmentacion de clientes.

URL: https://archive.ics.uci.edu/ml/datasets/online+retail

Uso: Caso #3 · Analisis de canasta real, manejo de devoluciones, segmentacion RFM.

🛒 Dunnhumby — The Complete Journey

Kaggle · 2019 · 2,500 hogares · 250K+ transacciones · Autoridad: Alta

Datos de compras de 2,500 hogares durante 2 años en una cadena de supermercados. Incluye: transacciones, productos, promociones (coupons), lealtad del cliente, demografia. Ideal para personalizacion de paquetes y analisis de respuesta a promociones.

URL: https://www.kaggle.com/datasets/frtgnn/dunnhumby-the-complete-journey

Uso: Caso #3 · Personalizacion de paquetes por perfil de hogar, respuesta a promociones, segmentacion.

🚛 Solomon Benchmark VRPTW

SINTEF · 1987 · 56 instancias · 100 clientes · Autoridad: Academica S

El benchmark estandar para Vehicle Routing Problem with Time Windows. 56 instancias con 100 clientes cada una, divididas en 6 clases (C1, C2, R1, R2, RC1, RC2) segun distribucion espacial. Cada cliente tiene coordenadas, demanda, ventana de tiempo, y tiempo de servicio.

URL: https://www.sintef.no/projectweb/top/vrptw/solomon-benchmark/

Uso: Caso #2 · Validacion del solver VRPTW, benchmarking contra soluciones optimas conocidas.

🚛 Gehring & Homberger VRPTW Benchmark

SINTEF · 1999 · 300 instancias · 100–1,000 clientes · Autoridad: Academica S

Extension de Solomon con instancias de mayor escala: 200, 400, 600, 800 y 1,000 clientes. Misma estructura de datos pero disenadas para probar algoritmos en escenarios de tamano real.

URL: https://www.sintef.no/projectweb/top/vrptw/gehring-homberger-benchmark/

Uso: Caso #2 · Pruebas de escalabilidad del solver, validacion con 200–1,000 tiendas.

🚛 TSPLIB — Traveling Salesman Problem Library

Universidad de Heidelberg · 1991 · 198 instancias · 14–85,900 nodos · Autoridad: Academica S

Libreria de instancias para TSP, ATSP, CVRP, SOP y HCP. Incluye coordenadas reales de ciudades alemanas, placas de circuito VLSI, y otras aplicaciones.

URL: http://comopt.ifi.uni-heidelberg.de/software/TSPLIB95/

Uso: Caso #2 · Pruebas unitarias de algoritmos de distancia y ruteo, benchmarking de performance.

🚛 Extended Solomon (Eco-VRP)

Atlantis Press · 2024 · 56 instancias base + metricas ambientales · Autoridad: Academica A

Extension del dataset Solomon con factores ambientales: emisiones CO2 (150 g/km), consumo energetico (0.2 kWh/km), congestion de trafico (factor 0.2–0.8), estaciones de carga EV (30 kW/h), y energia renovable.

URL: https://www.atlantis-press.com/article/126013773.pdf

Uso: Caso #2 · Ruteo con consideraciones de sostenibilidad, emisiones CO2, optimizacion multi-objetivo.
