B.3) Uso de setup-ssl.sh en Cambios de Host o de IP (Recomendado)
  1. Asegúrate de tener mkcert instalado en el sistema host (sudo apt update && sudo apt install -y mkcert).
  2. Posteriormente, descarga la nueva CA raíz en cada teléfono Android desde la nueva IP e instálala en la sección de Seguridad.
B.4) Método Alternativo Manual Paso a Paso

Si prefieres realizar el procedimiento de forma manual:

  1. Instale mkcert en el servidor local (ej: sudo apt install mkcert).
  2. Genere la Autoridad Certificadora local: mkcert -install.
  3. Cree los certificados para la nueva IP (ej. 192.168.1.100):
    mkcert -cert-file ../ssl/server.crt -key-file ../ssl/server.key 192.168.1.100 localhost 127.0.0.1.
  4. Reemplace los archivos generados en la carpeta ssl/ del host (que se monta en /etc/apache2/ssl en el contenedor web).
  5. Copie el certificado de la CA raíz pública (~/.local/share/mkcert/rootCA.pem) como www/ca.crt para permitir su descarga por red.
  6. Reinicie el contenedor de Apache: docker compose restart web.
  7. Instale el archivo ca.crt generado como Certificado de CA en los teléfonos clientes Android de prueba.
B.5) Servidor de Notificaciones en Tiempo Real (Swoole v6)

El servicio de WebSockets corre en el contenedor aislado swoole. La configuración de red interna permite la interoperabilidad directa con el servidor Apache/PHP-FPM.

  1. Ejecución del Servidor: El contenedor inicia automáticamente el script laesh-swbldi/commons/swoole_server.php en primer plano.
  2. Comando para ver Logs: docker compose logs -f swoole.
  3. Verificación manual de puertos: curl -I http://localhost:6003 (desde el host local) o internamente curl -I http://swoole:9502 (desde el contenedor web).

11. Seguridad, Resiliencia y Observabilidad

11.1. Protección Activa

  • Validación de entradas: Sanitización de datos en todos los endpoints para prevenir SQL injection (uso estricto de PDO prepare/execute).
  • Backup automático: Script cron cada hora: mysqldump laesh > /backup/laesh_$(date +%Y%m%d_%H).sql

→ Ver Issues Conocidos y Mitigaciones

11.2. Optimización y Seguridad de Apache en el Portal Web (.htaccess)

Se implementaron directivas de seguridad y optimización de transferencia (WPO) mediante la creación de un archivo de configuración .htaccess en la raíz del sitio web público (website/uipv1/.htaccess):

  • Compresión GZIP (mod_deflate): Habilitada para comprimir al vuelo recursos de texto plano (HTML, CSS, JS, SVG, JSON) antes de su transporte de red.
  • Políticas de Expiración de Caché (mod_expires):
    • Caché agresiva de 1 año para imágenes (formatos WebP, JPEG, PNG, SVG) y fuentes web, reduciendo el consumo de ancho de banda a 0 bytes en visitas subsecuentes.
    • Caché moderada de 1 mes para hojas de estilo estáticas (CSS) y archivos de lógica UI (JavaScript).
    • Sin caché (0 segundos) para el documento HTML, forzando al navegador a solicitar de forma síncrona el contenido dinámico del CMS en cada visita.

11.3. Radiografía de la Optimización Lograda (WPO)

La auditoría y ejecución de optimización sobre los recursos del portal arrojó métricas de rendimiento sobresalientes en la red local y simulación de producción:

  • Reducción de Peso de Recursos (Ahorro del 98%):
    • Peso Original (JPEG/PNG Raw): Superior a 70 Megabytes, lo cual hacía inviable la carga en conexiones móviles 3G/4G.
    • Peso Optimizado (WebP): Convertidos todos los activos a WebP (calidad 80%) y redimensionados (Hero a 1920px de ancho, secciones/áreas a 1000px). El peso total del directorio de imágenes se redujo a tan solo 1.5 Megabytes.
  • Optimización del Render Loop (LCP y Conectividad):
    • Preload del LCP: La imagen crítica del primer slide (RECEPCION.webp) se pre-carga de manera prioritaria vía la cabecera <link rel="preload"> para acelerar el renderizado visual inicial (Largest Contentful Paint).
    • Diferimiento de Red (Lazy Loading): Aplicación nativa de loading="lazy" y decoding="async" a las 48 imágenes y recursos vectoriales de secciones secundarias.
    • Diferimiento de Iframe (Google Maps): Se bloquea la descarga de scripts de Google Maps al inicio (evitando descargar ~600 KB innecesarios) usando data-src en el iframe. La carga ocurre dinámicamente solo si el usuario selecciona explícitamente la pestaña "Mapa Interactivo".
    • Pre-conexión de Servidores (Preconnect): Inyección de directivas preconnect para acelerar en 150-200ms el establecimiento de socket TLS con los servidores CDN de Google Fonts.

13.4. Runbook: Configuración Multi-Dominio laesh.mx

⚠️ Prerequisito Bloqueante: El dominio laesh.mx debe tener sus Registros DNS tipo A apuntando a 137.131.58.161 antes de ejecutar el Paso 3 (Certbot). Sin la propagación DNS, Certbot no podrá validar la titularidad del dominio y fallará.

Paso 1 — Configurar DNS en el Registrador de laesh.mx

En el panel del registrador de dominio (donde tienes administrado laesh.mx), crear los siguientes registros:

TipoNombre / HostValor / DestinoTTL
A@ (raíz, equivale a laesh.mx)137.131.58.161600 seg (o el mínimo disponible)
Awww (equivale a www.laesh.mx)137.131.58.161600 seg

Para verificar que el DNS propagó correctamente, ejecutar desde cualquier terminal:

# Verificar desde cualquier equipo con acceso a internet
dig +short laesh.mx
# Resultado esperado: 137.131.58.161

dig +short www.laesh.mx
# Resultado esperado: 137.131.58.161

# O desde el propio servidor OCI:
ssh ubuntu@oci-vm "nslookup laesh.mx 8.8.8.8"

Paso 2 — Crear el Vhost Nginx para laesh.mx (HTTP — Sin SSL aún)

Conectarse al servidor y crear el archivo de configuración:

ssh ubuntu@oci-vm

sudo tee /etc/nginx/sites-available/laesh.mx << 'EOF'
# ==============================================================
# VHost LAESH.MX — Bloc Digital y Sitio Web Corporativo LAESH
# IP Pública OCI: 137.131.58.161
# Administrador: Caelitandem / carlos@caelitandem.lat
# Creado: Agosto 2026
# ==============================================================

server {
    server_name laesh.mx www.laesh.mx;
    client_max_body_size 32M;

    # Raíz principal → uipv1 (maqueta preventa actualizada)
    root /home/ubuntu/n8n-php/mvps/laesh-ui/uipv1;
    index index.html index.php;

    location / {
        try_files $uri $uri/ =404;
    }

    # Activos estáticos compartidos (CSS, JS, fuentes WOFF2, imágenes WebP)
    location ^~ /laesh-web-assets-uipv1a {
        root /home/ubuntu/n8n-php;
        expires 365d;
        add_header Cache-Control "public, no-transform, immutable";
    }

    # Procesador PHP-FPM (para Proyecto 1 CMS y Proyecto 2 API)
    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/run/php/php8.1-fpm.sock;
        fastcgi_buffers 16 16k;
        fastcgi_buffer_size 32k;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
    }

    # Proxy WebSocket → Swoole v6 (Notificaciones Real-Time — Proyecto 2)
    # Activar cuando el contenedor Swoole esté en producción en puerto 9502
    # location /ws {
    #     proxy_pass http://127.0.0.1:9502;
    #     proxy_http_version 1.1;
    #     proxy_set_header Upgrade $http_upgrade;
    #     proxy_set_header Connection "Upgrade";
    #     proxy_set_header Host $host;
    #     proxy_set_header X-Real-IP $remote_addr;
    #     proxy_read_timeout 3600s;
    #     proxy_send_timeout 3600s;
    # }

    # Cabeceras de seguridad
    add_header X-Content-Type-Options nosniff always;
    add_header X-Frame-Options SAMEORIGIN always;
    add_header X-XSS-Protection "1; mode=block" always;
    add_header Referrer-Policy "strict-origin-when-cross-origin" always;

    # Compresión GZIP
    gzip on;
    gzip_types text/css application/javascript image/svg+xml application/json;
    gzip_min_length 256;

    # Caché de estáticos
    location ~* \.(css|js|png|jpg|jpeg|gif|svg|ico|woff2?|webp)$ {
        expires 30d;
        add_header Cache-Control "public, no-transform";
    }

    access_log /var/log/nginx/laesh.mx-access.log;
    error_log  /var/log/nginx/laesh.mx-error.log;

    # Certbot añadirá las directivas SSL/listen 443 automáticamente en el Paso 3
    listen 80;
    listen [::]:80;
}
EOF

Paso 5 — Obtener Certificado SSL con Certbot (Let's Encrypt)

13.8. Estrategia y Arquitectura de Fallbacks (Tolerancia a Fallos Web)

Para garantizar una alta usabilidad y disponibilidad en navegadores web (Desktop, Tabletas e iOS/Android) sin depender de arquitecturas de aplicaciones instalables (PWA/Apps), el proyecto implementa un sistema unificado de 5 niveles de fallbacks:

Tabla. Matriz de Fallbacks y Resiliencia en Frontend
#Nivel / CategoríaMecanismo / ImplementaciónUbicación en CódigoPropósito y Comportamiento
F-1 Accesibilidad y No-JS Etiqueta <noscript> con enlace alternativo directo a Google Maps uipv1/index.html (L. 1070) Si el usuario desactiva JavaScript o este falla en ejecutarse, en lugar del mapa interactivo bloqueado se despliega un hipervínculo plano seguro y accesible hacia la ubicación en Google Maps.
F-2 Pila Tipográfica (Font Stack) Fuentes WOFF2 locales con cascada al SO (San Francisco, Segoe UI, Roboto, sans-serif) laesh-web-assets-uipv1a/css/fonts.css Cabin y Outfit se sirven desde /fonts/ local sin dependencia de CDN. Si el WOFF2 no carga (disco lleno, permiso incorrecto), el CSS conmuta automáticamente a tipografías nativas del SO. Estrategia: offline-first — ninguna petición de red para renderizar texto.
F-3 Detección de Dispositivo y Capabilidades (Hardened) Script device-detect.js blindado con try-catch y soporte iPadOS 13+ Cargado en todos los HTMLs (L. 38/15) Clasifica de forma resiliente el SO (incluyendo iPadOS), navegador e input de toque/mouse. Cuenta con blindaje defensivo (try-catch) que garantiza 0% de interrupción en la carga si el navegador del cliente restringe la API dataset o CSSOM.
F-4 Sensibilidad a Animación Media query (prefers-reduced-motion: reduce) (WCAG 2.2.2) laesh-web-assets-uipv1a/css/style.css (MQs al final del archivo) y style-website.css Suspende automáticamente animaciones CSS, giros de tarjetas y transiciones de carrusel cuando el usuario tiene activa la preferencia de movimiento reducido en el SO. Las reglas residen en los archivos CSS de cada scope — nota: no existe responsive.css como archivo independiente; los MQs de responsividad están integrados en style.css y style-website.css.
F-5 Texto Alternativo y Decodificación de Imagen Atributos alt="..." descriptivos + decoding="async" + loading="lazy" Todas las etiquetas <img> (24 activos) Proporciona soporte de lectura en pantalla (WCAG 2.1) e impide bloqueos del hilo principal de renderizado si las imágenes se descargan lentamente en redes móviles.
