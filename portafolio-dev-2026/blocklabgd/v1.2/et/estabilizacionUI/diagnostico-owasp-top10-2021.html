Discrepancias Críticas: Especificación Teórica vs Código Fuente Real

Inconsistencias donde la documentación técnica declara un blindaje implementado que en el código fuente de producción no existe o presenta fallas de precedencia.

Discrepancia 1 · A08 Omisión Total de Verificación de Magic Bytes (%PDF-) en Subida de Resultados

Lo que declara la Especificación (Tecnica_Seguridad_Integral.html §5):

«Al adjuntar resultados, el sistema backend validará no solo la extensión, sino la firma binaria real (Magic Number %PDF-) mediante la extensión finfo. Si el archivo es un script malicioso enmascarado, será rechazado y eliminado instantáneamente.»

La realidad en el código (rc/index.php L2180-L2185):

rc/index.php — Manejador de subida de PDF
$file = $_FILES['pdf_file']; $ext = strtolower(pathinfo($file['name'], PATHINFO_EXTENSION)); if ($ext !== 'pdf') { $sendError('El archivo debe ser un documento PDF (.pdf).'); } // ❌ NO HAY USO DE finfo NI COMPROBACIÓN DE %PDF-

Impacto: Cualquier archivo arbitrario (HTML, JavaScript, binario, script PHP polyglot) renombrado a .pdf es aceptado por el servidor sin inspección de su contenido binario real.

Discrepancia 2 · A04/A05 Bypass Estructural de Rate Limiting en Nginx para el Endpoint de Login

En el archivo de configuración de producción (nginx-laesh-domain.conf), la directiva limit_req zone=login burst=3 nodelay; se declaró dentro de location /login/ (L282-L287). Sin embargo, la regla regex location ~ ^/login/(.+\.php)$ (L205-L211) se evalúa antes en el algoritmo de coincidencia de Nginx:

# Nginx evalúa expresiones regulares ANTES de prefix locations sin ^~
location ~ ^/login/(.+\.php)$ {
    fastcgi_pass unix:/run/php/php8.3-fpm.sock;
    # ❌ CARECE DE limit_req zone=login;
}

location /login/ {
    limit_req zone=login burst=3 nodelay; # ❌ INALCANZABLE para peticiones a /login/login.php
    alias /opt/laesh/www/laesh-swbldi/website/login/;
}

Impacto: Todo ataque de fuerza bruta dirigido directamente por POST a /login/login.php burla por completo la capa de protección de Nginx.

Discrepancia 3 · A01 Exposición de /libs/ y Fallback de Almacenamiento en Webroot
  • Falta de bloqueo Nginx para /libs/: Nginx bloquea ^~ /commons/, ^~ /crons/ y ^~ /tests/, pero omite ^~ /libs/. Peticiones HTTP a scripts dentro de libs/auth/ o libs/flight/ son despachadas y ejecutadas por PHP-FPM sin autenticación.
  • Fallback de subida inseguro: En rc/index.php (L2196-L2205), si /opt/laesh/uploads/pdfs/ falla, el uploader crea y escribe en laesh-swbldi/uploads/pdfs/ (dentro del webroot) con chmod 0777. Nginx solo bloquea ^~ /uploads/resultados/, dejando /uploads/pdfs/ expuesto a descarga pública directa.
01

A01:2021 — Broken Access Control (Pérdida de Control de Acceso)

Vulnerabilidades relacionadas con la autorización, control de rutas, IDOR y visibilidad de datos sensibles.

Puntos Fuertes Existentes
  • Guardias RBAC estrictas a nivel de controlador Flight PHP mediante Flight::rbac()->requirePermission() para Portales Recepción (gestionar_ordenes) y Administración (gestionar_cms).
  • Aislamiento de propiedad médica: el médico únicamente puede descargar resultados asociados a su propio medico_id (md/index.php L1060).
  • Arquitectura de entrega de PDFs fuera del webroot (/opt/laesh/uploads/pdfs/) mediante directiva internal; de Nginx y encabezado X-Accel-Redirect.
  • Autorización y segmentación de canales WebSocket en servidor Swoole con revocación forzada activa.
Gaps y Vulnerabilidades Identificadas
Elemento Afectado Vulnerabilidad / Gap Riesgo / Impacto
nginx-laesh-domain.conf Omisión de regla location ^~ /libs/ { return 404; }. Ejecución directa de scripts PHP internos de librerías de terceros sin pasar por Flight ni autenticación.
rc/index.php (L2197) Fallback de subida a uploads/pdfs/ en webroot con permisos 0777. Descarga pública directa sin autenticación si el directorio de producción falla en permisos.
rc/index.php (GET /orden/pdf) Falta de registro de auditoría en lecturas y descargas para rol RECEPCION. Descarga masiva de expedientes médicos sin trazabilidad de operador (no-repudio ausente).
02

A02:2021 — Cryptographic Failures (Fallas Criptográficas)

Cifrado de datos en reposo y en tránsito, gestión de llaves y almacenamiento seguro de credenciales.

Puntos Fuertes Existentes
  • Modelo de contraseñas en 5 capas: Bcrypt ($2y$) con salting CSPRNG aleatorio y pre-hash HMAC-SHA-512 con pepper secreto, neutralizando el límite de 72 bytes de Bcrypt.
  • Tokens JWT firmados con algoritmo HS256 utilizando LAESH_JWT_SECRET obligatorio en producción.
  • Tráfico web cifrado con TLS 1.2/1.3, curvas elípticas modernas (X25519) y HSTS de 1 año con includeSubDomains.
Gaps y Vulnerabilidades Identificadas
Área Gap Técnico Impacto Regulatorio / Operativo
Datos en Reposo (TDE) Ausencia de cifrado de base de datos en reposo para tablas clínicas (pacientes, ordenes) y PDFs en disco. Incumplimiento de normativas de expediente clínico electrónico (NOM-004-SSA3, NOM-024-SSA3, HIPAA/GDPR) ante sustracción física de discos.
Respaldos de Base de Datos backup_db.sh genera archivos .sql.gz en texto plano sin cifrado simétrico (GPG/AES). Exposición total de la información clínica y hashes si se compromete el directorio de backups.
Cookies de Sesión commons/commons.php no establece session.cookie_samesite = 'Lax' en la sesión nativa de PHP. Potencial envío no deseado de cookies de sesión en solicitudes cross-site en navegadores antiguos.
Telemetría SQL Uso de CRC32 para indexar huellas de consultas SQL en fallback_log. Colisiones frecuentes de hash impidiendo agrupar incidencias SQL correctamente.
03

A03:2021 — Injection (Inyección)

Inyección SQL, Cross-Site Scripting (XSS), inyección en logs y sanitización de entradas.

Puntos Fuertes Existentes
  • Prevención SQLi integral mediante PDO Prepared Statements y Stored Procedures (cero concatenación directa).
  • Principio de mínimos privilegios en MariaDB: usuario laesh_app restringido exclusivamente a DML (sin permisos DDL ni DROP).
  • Escape contextual en plantillas Plates vía htmlspecialchars().
  • Parche para XSS almacenado en notificaciones WebSocket implementado en ws-client.js (función escapeHtml).
Gaps y Vulnerabilidades Identificadas
  • CSP Permisiva con 'unsafe-inline' y CDN no acotado: La cabecera Content-Security-Policy declara script-src 'self' 'unsafe-inline' https://unpkg.com. Permitir 'unsafe-inline' inutiliza la protección del navegador contra XSS reflejado y almacenado. Además, unpkg.com permite cargar cualquier script público de NPM sin comprobación de integridad.
  • Inyección HTML en CMS sin HTMLPurifier: CKEditor 5 guarda contenido HTML enriquecido en web_contenidos. El backend carece de una librería de sanitización estricta del lado del servidor que purgue atributos maliciosos (ej. onload, onerror, iframe) antes de persistir en base de datos.
  • Log Injection (CRLF): Entradas del cliente (encabezados HTTP, cadenas de búsqueda) no se limpian de caracteres de salto de línea (\r\n) antes de volcarse en app.log.
04

A04:2021 — Insecure Design (Diseño Inseguro)

Limitaciones de arquitectura, ciclo de vida de sesiones médicas y políticas de contraseñas.

Gaps y Vulnerabilidades Identificadas
Vector de Diseño Descripción del Defecto Lineamiento Vulnerado
Políticas de Contraseña / NIP Restricción obligatoria de exactamente 10 caracteres en formularios de cambio y asignación de contraseñas. NIST SP 800-63B y OWASP prohíben exigir longitudes exactas y recomiendan permitir frases de paso de 8 a 128 caracteres.
Credenciales por Defecto Fallback de contraseña hardcodeada '04041974' en Ordenes.php L1210 y uso de fecha de nacimiento ddmmaaaa como contraseña inicial. Baja entropía y alta predictibilidad de credenciales para actores maliciosos mediante ingeniería social.
Configuración Dinámica de Rutas cms_upload_dir editable desde la interfaz web administrativa (admrc/views/sistema.php). Diseño inseguro: una variable en BD define rutas absolutas en el sistema de archivos del servidor sin lista blanca rígida.
Expiración de Sesión Médica Ventana de sesión médica extendida a 90 días (7,776,000s) en producción. Ventana de ataque excesiva en terminales compartidas o dispositivos móviles clínicos desatendidos.
05

A05:2021 — Security Misconfiguration (Configuración de Seguridad Incorrecta)

Hardening de Nginx, parámetros de PHP-FPM, UFW y herramientas anti-escaneo.

Gaps Documentados como "Pendientes" en Producción

En el documento maestro Tecnica_Seguridad_Integral.html §7 se listan tres capacidades defensivas críticas marcadas como pendientes:

  • §7.3 Bloqueo Nginx de Rutas CMS Ajenos (444 — Sin Respuesta): ⏳ Pendiente aplicar. Actualmente scanners automáticos de WordPress/Joomla siguen consumiendo workers de Nginx.
  • §7.4 Rate Limiting Global en Proxy PHP (limit_req zone=api): ⏳ Pendiente aplicar. La zona de 30 req/min no está activa en el bloque principal del proxy PHP-FPM.
  • §7.5 Fail2ban — Baneo Automático de IPs Agresivas: ⏳ Pendiente instalar. El servidor carece de bloqueo reactivo automatizado ante escaneos de red repetidos.

Configuraciones Obsoletas Adicionales:

  • Uso de la cabecera obsoleta X-XSS-Protection: 1; mode=block en Nginx y en commons.php.
  • Ausencia de la directiva open_basedir en PHP-FPM para confinar el acceso de la aplicación a su propio árbol de directorios.
  • Persistencia de credenciales root en texto claro en /opt/laesh/configs/.mariadb-root.cnf.
06

A06:2021 — Vulnerable and Outdated Components

Gestión de dependencias de terceros, parches de seguridad y escaneo automatizado.

Gaps Detectados
  • Carencia de Auditoría Automatizada de Dependencias (composer audit): Debido a la arquitectura frugal, librerías como Delight Auth, Flight PHP y Plates están embebidas en libs/ con autoloader manual sin utilizar composer.lock en tiempo de ejecución. No existe un paso en el pipeline que alerte sobre CVEs conocidos en estas dependencias.
  • Falta de Subresource Integrity (SRI) en CDN: CKEditor 5 se importa desde https://unpkg.com sin verificar hash criptográfico (integrity="...").
07

A07:2021 — Identification and Authentication Failures

Mecanismos de autenticación, control de fuerza bruta y gestión de identidad.

Gaps Detectados
  • Inexistencia de Autenticación Multifactor (MFA / 2FA): Los portales administrativos (ADMIN) y operativos (RECEPCION) dependen exclusivamente de un solo factor (teléfono + contraseña/NIP). No hay soporte para TOTP (Google Authenticator) ni llaves de seguridad para roles con acceso total a la base de datos de pacientes.
  • Bypass del Rate Limiter en Nginx: Como se detalló en la Discrepancia 2, el rate limiter de 5 req/min de Nginx se omite para peticiones directas a /login/login.php, recayendo toda la protección únicamente en el throttling a nivel de base de datos de Delight Auth.
08

A08:2021 — Software and Data Integrity Failures

Validación de integridad en cargas de archivos, serialización y cadenas de suministro.

Gaps Detectados
  • Omisión de Magic Bytes en Subida de PDFs: En rc/index.php (L2181-L2184) solo se evalúa la extensión del archivo ($ext !== 'pdf'), sin verificar finfo(FILEINFO_MIME_TYPE) ni la firma de cabecera binaria %PDF-.
  • Ausencia de Motor Antivirus / Antimalware (ClamAV): No existe inspección contra virus/troyanos en archivos PDF que el personal de recepción carga desde memorias USB o laboratorios externos.
09

A09:2021 — Security Logging and Monitoring Failures

Monitoreo activo de incidentes de seguridad, trazabilidad de accesos y protección de bitácoras.

Gaps Detectados
  • Alertas de Monitoreo Limitadas a Disponibilidad (Sin Alertas de Seguridad): El cron monitor_services.sh y las alertas SMTP solo monitorean caídas de servicios (Nginx, MySQL, PHP-FPM, Swoole). No disparan alertas ante ataques de fuerza bruta continuados, violaciones de tokens CSRF ni accesos no autorizados (403 IDOR).
  • Bitácoras Locales Vulnerables a Manipulación: Los logs residen exclusivamente en el servidor local sin reenvío cifrado a un colector externo (Rsyslog / SIEM), impidiendo garantizar el no-repudio ante compromiso de la máquina.
  • Falta de Auditoría en Lectura de Resultados: No se genera log de auditoría cuando un usuario con rol de recepción descarga o consulta un resultado clínico.
10

A10:2021 — Server-Side Request Forgery (SSRF)

Peticiones externas del lado del servidor y control de tráfico saliente.

Gaps Detectados
  • Reglas Salientes de UFW Permisivas (Egress Filtering Abierto): UFW tiene configurado default allow outgoing. En caso de compromiso del servidor web, no existen restricciones de firewall para evitar conexiones salientes hacia servidores C2 o descarga de payloads externos.
  • Validación de Esquema en Enlaces Externos del CMS: Los enlaces de redes sociales (WhatsApp, Facebook) configurables en el CMS deben forzarse en el backend a validar estrictamente esquemas https://.

Plan de Acción y Matriz de Mitigación Inmediata

Tareas priorizadas para cerrar los hallazgos críticos y estabilizar la postura de seguridad defensiva en producción.

Prioridad OWASP Hallazgo Acción de Mitigación Inmediata
P0 · Crítico A08 Subida de PDFs sin validación de Magic Bytes en rc/index.php. Implementar validación con \finfo comprobando MIME application/pdf y verificar que los primeros 5 bytes comiencen exactamente con %PDF-.
P0 · Crítico A01 Exposición de /libs/ sin protección en Nginx. Añadir location ^~ /libs/ { return 404; } y location ^~ /setup/ { return 404; } en nginx-laesh-domain.conf.
P0 · Crítico A04 Bypass de Rate Limiting en /login/login.php. Mover limit_req zone=login burst=3 nodelay; al bloque location ~ ^/login/(.+\.php)$.
P1 · Alto A05 Gaps §7.3, §7.4 y §7.5 pendientes en producción. Activar el bloqueo 444 contra scanners en Nginx, aplicar limit_req zone=api al proxy PHP e instalar Fail2ban.
P1 · Alto A02 Backups de base de datos sin cifrado. Actualizar backup_db.sh para cifrar los volcados .sql.gz con GPG simétrico antes de almacenarlos en disco.
P1 · Alto A03 CSP con 'unsafe-inline' y CDN abierto unpkg.com. Migrar scripts en línea a archivos estáticos con nonce/hash y alojar localmente los assets de CKEditor eliminando dependencias de CDNs abiertos.
P2 · Medio A04 Contraseña forzada a 10 caracteres exactos y fallback débil. Permitir longitudes flexibles (mínimo 10, máximo 128) y erradicar valores iniciales predecibles derivados de fechas de nacimiento.
P2 · Medio A09 Falta de auditoría de lectura de expedientes. Registrar en sys_logs cada acceso a GET /orden/pdf con user_id, orden_id e IP del solicitante.
P3 · Bajo A02 Cifrado en reposo (TDE) ausente en MariaDB. Activar el plugin de cifrado de tablas de MariaDB para la base de datos de pacientes y órdenes clínicas.
