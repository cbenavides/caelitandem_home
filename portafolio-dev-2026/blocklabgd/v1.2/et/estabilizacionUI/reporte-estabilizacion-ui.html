📋 Reglas de Validación Permanente

Checklist vivo derivado de todas las auditorías. Verificar contra cualquier archivo HTML/CSS/JS antes de commitar.

CSS
R-CSS-01

Ningún !important en landing.css, style.css, portal.css, tokens.css. La especificidad jerárquica nativa siempre es la solución.

grep -n '!important' landing.css style.css portal.css

R-CSS-02

Ningún atributo style="..." inline en HTML. La única excepción aceptada: JS que asigna element.style.top/left para posicionar overlays position:fixed.

grep -n 'style="' index.html gestion-web.html

R-CSS-03

Sin reglas CSS muertas: una propiedad declarada y sobreescrita por otra regla en el mismo bloque @media debe eliminarse. La segunda declaración anula a la primera sin aplicarla.

R-CSS-04

La propiedad transition debe vivir en un selector permanente, nunca en una clase que JS toggle. Al remover la clase se pierde el transition y la animación de regreso colapsa sin transición.

Verificar: clase con transition ∩ clases que JS añade/quita

R-CSS-05

Jerarquía de z-index obligatoria: navbar(1050) < hamburger(1051) < floats(1001) < tooltip(≤1500) < modal(2000) < cookie-banner(9500) < skip-link(9999). Los overlays temporales nunca superan a su modal padre.

R-CSS-06

En columnas de grid dinámico usar minmax(0, 1fr), no 1fr. 1fr equivale a minmax(auto, 1fr) — el mínimo auto puede exceder el contenedor y romper el layout.

R-CSS-07

Toda clase referenciada en HTML debe tener una regla CSS o una referencia JS. Las clases huérfanas (sin definición en ningún archivo) son deuda oculta y deben eliminarse.

grep class index.html | cruzar con landing.css + website.js

JavaScript
R-JS-01

Claves de objetos lookup: solo apóstrofes rectos U+0027 ('). Nunca U+2018/U+2019 (comillas tipográficas ''). textContent.toLowerCase() preserva el codepoint exacto del HTML.

node -e "require('fs').readFileSync('website.js','utf8').match(/[‘’]/g)"

R-JS-02

Tras modificar contenido DOM, leer offsetHeight/offsetWidth siempre dentro de requestAnimationFrame(). Sin rAF, el navegador aún no refluyó y devuelve dimensiones del contenido anterior.

R-JS-03

Para verificar si un iframe lazy ya tiene src: usar iframe.getAttribute('src'), nunca iframe.src. El getter DOM resuelve "" a la URL completa de la página actual.

R-JS-04

Tooltips que usan mouseenter/mouseleave deben tener también un handler click con e.stopPropagation() para dispositivos touch. No asumir capacidades hover.

HTML
R-HTML-01

Botones de acordeón: solo clases con definición real en CSS o JS. No añadir clases de "estado inicial" (p.ej. collapsed-btn) sin que exista una regla o referencia correspondiente.

R-HTML-02

Patrón lazy iframe: src="" + data-src="URL". JS inyecta el src real con getAttribute('data-src') al primer evento de interacción, no en carga de página.

Hero / Slider — Desktop, Tableta y Teléfono
R-HERO-01

Desktop — background-size: 85% auto, no cover. Declarada una sola vez en .hero-slide base. Ninguna regla .bg-slide-N repite esta propiedad (DRY). cover recorta laterales y está prohibido en el hero.

grep 'background-size' landing.css | grep 'bg-slide' → debe devolver vacío

R-HERO-02

Focal point por imagen. Cada .bg-slide-N declara solo background-image + background-position. Slide-1: center 30%, Slide-4: center 40%, resto: center center.

grep -A2 'bg-slide-' landing.css → solo image + position por regla

R-HERO-03

Estrategia de altura: vh+min+max (desktop) y vw+min+max (móvil). Desktop ≥1025px: 70vh / 500px / 800px. Tableta ≤1024px: 45vw / 260px / 500px. Teléfono ≤767px: 47vw / 200px / 360px. Nunca altura fija en px.

R-HERO-04

Tableta y teléfono usan background-size: contain. Imagen landscape completa, sin recorte lateral. Solo se declara en el breakpoint, nunca en .bg-slide-N.

R-HERO-05

DRY: padding-bottom solo en el base. El valor 2.2rem de .hero-slide controla el espacio tarjeta↔dots en todos los dispositivos. Ningún breakpoint lo redeclara. Teléfono solo sobreescribe padding-top y padding-inline.

grep 'padding-bottom' landing.css | grep 'hero-slide' → solo en base, no en @media

R-HERO-06

Sin gradiente sobre la imagen del hero. No usar linear-gradient() combinado con la imagen de fondo en .hero-slide ni en atributos style del PHP. El oscurecimiento para legibilidad lo provee el backdrop-filter: blur() de la tarjeta glassmorphic.

grep 'linear-gradient' index.php → debe devolver vacío en sección hero

R-HERO-07

Selectores h1/h2 unificados para los 5 slides. Slide-1 usa <h1> (semántica de página); slides 2–5 usan <h2>. El CSS los iguala con: .hero-glass-card h1, .hero-glass-card h2 { … }. No declarar estilos separados por slide.

R-HERO-08

Teléfono — priorización de contenido: ocultar <p>. El hero mide ~200px; espacio disponible ~140px. Badge+h1+p+botón ≈ 159px → desborde. Se oculta el párrafo (display:none), el menos crítico para la acción del usuario. Alternativa descartada: comprimir fuentes (0.88rem h1, 0.6rem p) — resultado ilegible.

R-HERO-09

Botones hero — especificidad 0,4,0 para cancelar targeting.css. targeting.css aplica min-height: 44px en táctil (0,3,0). Usar .hero-slide .hero-glass-card .flex-center-15 .btn-outline-white { min-height: unset } para superarlo. Tableta: 7px 18px / 0.8rem. Teléfono: 5px 13px / 0.72rem.

Verificar especificidad del selector override ≥ (0,4,0) en landing.css

R-HERO-10

Teléfono — botón pausa: solo icono, circular. .hero-pause-label { display:none } oculta el texto "Pausar/Reanudar". .hero-pause-btn { width:30px; padding:0; border-radius:50% } lo convierte en círculo compacto. En tableta y desktop el botón mantiene la pastilla con texto.

Performance — Carga Móvil
R-PERF-01

LCP preload obligatorio para slide-1. La imagen del primer slide del hero debe tener <link rel="preload" as="image" fetchpriority="high"> en el <head>, antes de los <link> CSS. El browser la descarga antes de parsear el CSS que la referenciaría.

grep 'preload.*image.*fetchpriority' index.php | head -1

R-PERF-02

IntersectionObserver inline al final del <body>. El observer de .animate-on-scroll debe registrarse en un script inline antes de los <script defer>. El inline corre al terminar el parseo del DOM, sin esperar descargas de red. Un flag window._laeshObserver previene registro duplicado desde website.js. El inline incluye fallbacks para prefers-reduced-motion y navegadores sin IntersectionObserver.

grep '_laeshObserver' index.php → debe aparecer antes del primer <script defer>

R-PERF-03

htmx: async fetchpriority="low", nunca defer. Con defer, htmx bloquea el evento DOMContentLoaded (el browser espera todos los defer antes de dispararlo). async + low: descarga en background con menor prioridad de red, ejecuta cuando llega, sin bloquear nada.

grep 'htmx.min.js' index.php → debe tener async y fetchpriority="low"

R-PERF-04

Lazy-load CSS para background-image de slides inactivos. Los browsers descargan background-image de elementos con opacity:0. Para prevenir descarga de slides 2–5: .hero-slide:not(.active) { background-image: none !important; }. El !important es la excepción aceptada: necesario para superar el bg_style inline del CMS.

grep 'hero-slide:not' landing.css

R-PERF-05

Toda <img> below fold requiere loading="lazy" decoding="async". Las imágenes con loading="eager" o sin atributo descargán bloqueando el critical path. La única excepción: logo en navbar (siempre visible) y LCP slide-1 (preload explícito). Aplica también a imágenes hardcodeadas en PHP (tarjeta Domingo en promociones).

grep -n '<img' sections/*.php | grep -v 'loading' → debe devolver vacío

R-PERF-06

Atributos width y height en <img> deben reflejar dimensiones intrínsecas reales del archivo. El browser usa el ratio declarado para reservar espacio antes de la descarga (prevención de CLS). Si el archivo es 800×580, declarar width="800" height="580". CSS controla el display real (object-fit, height fija). El mismatch provoca layout shift cuando carga la imagen.

Cruzar dimensiones de archivo con atributos HTML para imágenes de carrusel y galería

11 PERF-IMG-DIM Atributos width="400" height="200" no reflejan dimensiones intrínsecas reales de las imágenes de carrusel. Imágenes reales: 1000×562, 1000×1000, 999×666. El browser reserva espacio 2:1 pero la imagen carga en su ratio real → CLS. Para retina (2×DPR), imágenes 1000px se sirven a dispositivos que muestran ~400px → sobre-descarga. Pendiente Dimensión recomendada de entrega: 800×580 WebP (2× retina, ratio ~2:1 alineado con CSS height:290px + object-fit:cover). Atributos HTML: width="800" height="580". El creador de imágenes debe entregar en esas dimensiones o el responsable optimiza con Squoosh: resize a 800×580, WebP Q75, Effort 6. → Ver R-PERF-06.
12 PERF-VCACHE ?v=time() en CSS/JS impide todo cacheo del browser. 6 archivos CSS + website.js = ~51 KB gzip descargados frescos en cada visita. En móvil con WiFi débil este es el mayor multiplicador de latencia percibida en recargas. ⏸ Paused Dev Cambiar a ?v=<?= @filemtime(path) ?> al pasar a producción. En desarrollo, ?v=time() es intencional para evitar falsos positivos por caché.
