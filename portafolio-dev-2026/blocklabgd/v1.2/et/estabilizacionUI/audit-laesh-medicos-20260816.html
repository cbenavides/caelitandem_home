CRÍTICOCSS-01 overflow-y: auto en .main-content clipea el .ficha-dropdown absolutamente posicionado — raíz causa de P-LAESH-06 Issue A ▶

Según la especificación CSS, un elemento con overflow: auto/hidden/scroll crea un scroll container que clipea a sus descendientes absolutamente posicionados cuando el containing block de esos descendientes es un hijo del scroll container.

Cadena: .main-content { overflow-y: auto } (style.css línea 558) → .ficha-wrap { position: relative } (containing block) → .ficha-dropdown { position: absolute }. Porque .main-content es ancestro de .ficha-wrap, el dropdown ES clipado cuando desborda el área de scroll, especialmente en el eje Y (dirección en que se abre el dropdown).

Adicionalmente: cuando overflow-y es distinto de visible, el computed value de overflow-x (no explicitado) se convierte en auto, creando clipping en ambos ejes.

Este hallazgo explica el Issue A de P-LAESH-06 no identificado en 9 iteraciones. La solución requiere cambiar la estrategia de posicionamiento: position:fixed con coordenadas vía JS, o insertar el dropdown como hijo directo del body (portal pattern).

CRÍTICOA11Y-01 role="dialog" en ficha-dropdown sin aria-modal="true" ni focus trap — WCAG 2.1 SC 2.1.2 ▶

18 fichas tienen role="dialog". Requisitos WCAG incumplidos: ① aria-modal="true" para indicar a AT que el fondo es inert. ② Focus trap: Tab/Shift+Tab deben quedar dentro del dialog — actualmente solo se cierra con Escape. ③ Focus al abrir: primer elemento enfocable debe recibir foco automáticamente.

CRÍTICOA11Y-02 Botones "Crear e Imprimir" y "Limpiar" sin aria-label — en móvil el texto queda oculto y los SVG sin nombre accesible ▶

En móvil (≤767px), .btn-imprimir-texto { display: none !important; } oculta el texto de ambos botones dejando solo SVG icons. Los botones (líneas 172 y 176) no tienen aria-label y los SVG no tienen <title>. Nombre accesible vacío en móvil. Violación WCAG 4.1.2.

ALTOA11Y-03 .panel-nueva-orden-title { display:none } en móvil elimina el contexto del panel para screen readers ▶

display:none oculta tanto visualmente como para AT. Un usuario de screen reader en móvil no escucha "Nueva Orden" antes de llegar al formulario. La clase .visually-hidden ya existe en style.css (líneas 94–102) y debe usarse en su lugar.

ALTOA11Y-04 Badge #total-estudios-badge no existe en el HTML actual — posible regresión de Gemini ▶

El CSS define .total-estudios-badge pero el HTML actual de tab-bar-btns (líneas 170–180) solo contiene los dos botones — no hay <span id="total-estudios-badge">. Si JS lo inserta post-carga, los AT no registran la región aria-live correctamente.
